# fuel-v1.2 边界表

`fuel-v1.2` 的完整保护候选使用 `join-span-debit-first-v1` 布局。它复用
`fuel-v1` 的 opcode 允许表、静态权重、动态费用、i64 初始预算和
`diagnostics-v1` 指令站点。布局比较中的 `p0`、`p1`、`p2` 和 `p2-prefix`
仍使用 `fuel-v1`，可复现旧模型和试点对照。新模型的布局共享以下分段规则。

[v1.2 模型指纹](fuel-v1.2.sha256) 依次串接 `cost_model.mbt`、`join_fuel.mbt`
及本文的 UTF-8 内容，统一使用 LF，以一个 NUL 字节分隔，再计算 SHA-256。

| 源指令或控制流位置 | 划分规则 |
| --- | --- |
| 函数入口 | 从首条计费指令开始 |
| `if` | `if` 本身计入当前 span。then、else 和实际汇合后的第一条计费指令分别开新 span。空臂无需站点 |
| `loop` | `loop` 本身计入当前 span。循环体首条计费指令开新 span，回边进入同一站点 |
| `block` | `block` 本身及顺序进入的块体可合并。被分支引用的块标签在块结束后的第一条计费指令开新 span |
| `br`、`br_if`、`br_table` | 分支指令计入当前 span 并结束它。`br_if` 落穿处开新 span。解析所有 `br_table` 标签和默认标签 |
| `return`、`unreachable` | 指令计入当前 span 并结束它 |
| grow、bulk memory/table | 静态基本费自成一个 span，原站点继续执行动态费用及 Growth 检查 |
| 其余静态指令 | 连续合并，含 load、store、`global.set`、除法和 call。调用点仍执行 Stack 检查 |
| 长度上限 | 每 span 最多 19 条计费指令。达到上限后从下一条计费指令重新开始 |

结构体内部按原指令先序编号。`else` 和 `end` 既不收费，也不占站点。
未被分支引用的块出口、顺序退出的循环体以及唯一落穿的显式 else 可以
与后续指令共用 span。站点须在先序中连续，因此有显式 else 时 then
与 if 后续指令分别计费。
分支切分保证一个 arm 或落穿路径不会扣取另一条路径的静态费用。
不可达源指令仍有站点，词法标签引用仍保留切分点。已终止路径中的跳转
不能让它重新成为结构汇合的可达前驱。

## 扣费和回放

profile 为一个 64 位字。低 57 位按源站点顺序存放 19 个三位权重，最低位
起存首条指令。编码 `1`–`5` 表示同值权重，`6` 表示 grow 的 8，`0`
填充未使用的位置，`7` 保留。高 7 位无符号存放静态总费用 `W`。grow
独立计费，因此 `1 ≤ W ≤ 19 × 5 = 95`。

初始预算由 `FuelConfig::new` 和 CLI 的十进制 i64 解析检查，范围为
`[1, 2^63−1]`。低余额可以为零。成功扣费后的 `B` 仍在 `[0, 2^63−1]`。
因为 `B` 和 `W` 均严格小于 `2^63`，`B − W` 在有符号 i64 中可表示，
其符号等价于 `B < W`。这个判据只用于已知静态费用。动态费用继续执行
既有的 i64 上界和乘法防护。

热路径为 `global.get / i64.const W / i64.sub / global.set / global.get /
i64.const 0 / i64.lt_s / if`，不新增静态扣费用局部变量。每模块至多一个
静态失败 helper。冷路径传入首站点、已扣 `W` 的有符号余额和 profile。
helper 从 profile 恢复 `W` 和扣费前余额，按各条权重回放可支付前缀，把
剩余预算写回，然后设置 Fuel 诊断和第一条不可支付的源指令站点并陷阱。
冷路径只回放费用。当整段不足以支付时，原段在入口失败。整段预扣成功
后若中途发生原生陷阱，后缀的静态预扣保留，原生陷阱仍发生在源操作处。

## 迁移与验证

生产配置可通过 `--cost-model fuel-v1.2` 或 `--codegen join-span` 选择。
同时提供两项时，模型和布局必须匹配。产物 marker 和 manifest 均记录
`fuel-v1.2` 与 `join-span-debit-first-v1`。sidecar 的 `fuel_spans` 列出
每段的 `first_site` 和 `length`，原 `sites` 继续逐条映射源指令。
`instrument verify` 会交叉检查 manifest 模型、布局、marker 和 Wasm 摘要，
并从实际计费 guard 的冷路径参数还原 span 首站点及长度，与 sidecar 核对。

旧产物保留其 `fuel-v1` 标签，迁移时用未经插桩的原件重建产物及清单。
已插桩产物会被输入策略拒绝。用于 S27 独立预言机重推导的入口为
[integration/fuel_oracle](../../integration/fuel_oracle/README.md)。

## 缓存布局及 Stack 预算打包

`--codegen join-span-cached` 选择 `join-span-packed-cache-v1`，继续使用
上述边界表、权重编码、诊断站点和同一个冷路径回放。冻结的
`join-span-debit-first-v1` 仍可单独选择。

至少两个 span、且没有动态费用的原函数可以用一个 i64 local 暂存余额。
每次预扣仍在原 span 入口执行并判断符号。调用前同步到全局余额，调用返回
后重新加载，包括导入调用和间接调用。可陷阱操作及函数出口前同步余额，
其中显式 `return` 和跳到隐式函数标签的分支都属于出口。扣费失败时共享
helper 从局部的扣后余额恢复原余额，回放并写入与原布局相同的剩余值。

当两个 Stack 上限和所有 `C` 都能容纳于 31 位正数时，剩余单位和深度分别
在一个私有 i64 的低、高 32 位中。Wasm 声明保留两个初始预算供 Linux
runner 校验。第一次进入导出或 start 包装器时完成打包，并将私有 depth
全局置零作为已初始化标志，后续调用及重入沿用该状态。
一次减去 `(1 << 32) + C` 后，低位符号
位检测单位不足。低位借位已经意味着 Stack 失败，因此高位只在低位有效
时决定 Depth。非叶路径在失败写诊断前恢复原字，正常返回时一次加回同样的
量。更宽的合法配置走两个 i64 计数器的路径。

能静态确定目标是被定义的、没有原调用指令的直接调用仍在入栈前检查相同的
`C` 与深度。其预留可以隐含在这次检查中，因为调用期间没有内层调用可以
观察它，也没有从该函数发起宿主重入的路径。每个函数的真实帧和生成辅助
路径仍经 `A ≤ C` 审计。导入、间接调用及入口包装保留显式预留与归还。
