# fuel-v1 计费契约

版本为 `fuel-v1`。完整、逐 opcode 的权重和分类见 [cost_model.mbt](../../cost_model.mbt)。
键是规范的 core Wasm 助记符，带类型与不带类型的 `select` 使用同一键；对立即数、类型、资源索引和 profile 的核验仍须单独通过。
缺失规则必须拒绝，不能默认收费。存在定价规则也不能放宽 [支持矩阵](support-matrix.md)，包括固定 funcref 表的引用限制及 externref/bulk 条件项。
这些权重是工程配额。固定操作以 1 为基本单位，部分算术计算为 2，内存访问为 3，可能 trap 的整数除余与截断为 4，直接/间接调用分别为 3/5。S25 收敛支持范围后，SIMD 全部拒绝。
发布校验使用 [S25 后的模型指纹](fuel-v1-simd-free.sha256)。指纹是 `cost_model.mbt` 的 UTF-8 字节、一个 NUL 字节及本文 UTF-8 字节拼接后的 SHA-256，两文件换行统一为 LF。[S20 指纹](fuel-v1.sha256) 保留用于复现 `f3492f5` 的实验历史。改动定价、规范边界、失败顺序或 site 编号时必须升级模型并重跑验证。

## 动态费用

| 原指令 | 静态基础 a | 系数 b | n |
| --- | ---: | ---: | --- |
| `memory.copy/fill/init` | 4 | 1 | 请求字节数 |
| `table.copy/fill/init` | 4 | 2 | 请求元素数 |
| `memory.grow` | 8 | 64 | 请求页数 |
| `table.grow` | 8 | 4 | 请求元素数 |

预算范围为 `1..=i64::MAX`。原始 i32 长度按 unsigned 拓宽。块静态预扣已含 a，
动态检查验证总数学成本 `a+b*n`，通过后只额外扣 `b*n`。当 b 大于零时先检查
`n <= (i64::MAX - a) / b`。b 为零只保留 a，n 为零时动态扣减为零。
任一比较失败时当前扣减不生效，已成功的静态预扣保留。原始 grow 返回失败值或原始操作 trap 均不退款。
所有冻结系数和 u32 长度的组合都可表示为 i64，溢出分支仍须实现，并以人工系数检验。

## Canonical 分块

按原指令结构和控制流决定边界。P0/P1/P2 使用同一划分。
常量表达式、结构分隔符 `else/end`、生成的 helper/wrapper 没有额外指令费用。

| 情形 | 划分规则 |
| --- | --- |
| 函数入口、分支目标、条件分臂入口、结构体入口与结构汇合、转移的合法后继 | 标记为块首，禁止跨块首合并。空路径不产生虚构费用。 |
| `Prefix` | 从块首贪心并入下一条必经的同块指令。仅允许无 trap、无外部可观察副作用的指令作前缀。 |
| `Barrier` | 可吸收同块必经的安全前缀，随后结束该块。调用、动态操作、标量 load/store、可能 trap 的算术、可观察写入及分支均遵守此规则。 |
| `block` 与 `if` | 费用归入其所在的入边块并结束该块。内部路径从独立块首开始。未选分支不付费。 |
| `loop` | 进入 loop 前断块。loop 原指令的权重放在循环体块首，首次进入和每次回边都支付。可与首段安全前缀及其末尾 barrier 合并。 |
| `br_if` / `br_table` | 原指令是块末。每个可能的转移目标及存在的 fallthrough 独立为块首。 |
| `return` / `unreachable` | 作为块末停止；后续不可达指令不在该块预扣。 |

在块首按 i64 检查并一次性预扣原指令权重和，构建期累加溢出时拒绝模块。
例如 `local.get; i32.load; i32.const; i32.store` 切成两个块，分别预扣 4 和 4。
第一处 load trap 时第二块未收费。循环回边只能经原始控制转移回到 loop 头，
所有回边都重付权重 1 的 loop 头，因此域内不存在零费用循环。

## Site 与失败顺序

按原模块的函数索引升序排列定义函数，函数内对原始指令做词法前序编号（从 0 开始，结构指令先于子体，then 先于 else，结构分隔符不编号）。
块 site 以第一条原指令序号为锚。sidecar 记录块区间及末尾边界指令序号。
同一函数的 export/start 外部入口共享独立的入口 site，并排在该函数第一个块之前。
按此顺序为所有规划 site 分配从 1 开始的 ID，0 保留。编号以词法计划为准，不随实际分支、运行次数或 codegen 布局改变。静态块预算失败与该块末尾的资源、动态费用或调用预留失败使用同一个块 site。

1. 普通块先检查并扣静态费用。动态操作保持原始操作数求值顺序，保存一次，随后检查资源上限（code 2/3），再检查动态溢出或不足（code 1），最后执行原操作。
2. 直接调用先付静态费用，再检查栈单位（code 4）、逻辑深度（code 5），通过后预留并调用，正常返回释放。callee 入口独立计费。
3. 间接调用先付静态费用，再由引擎完成索引、null、类型检查。仅合法目标的 wrapper 检查栈、深度并预留。wrapper 使用原调用点的块 site，非法目标保留原生 trap。
4. 外部 export/start wrapper 在原函数首个 Fuel 块之前检查栈、深度。生成辅助函数不引入额外的预算事件。

## 独立预言机

`python -m unittest discover -s integration/fuel_oracle -v` 执行手算轨迹。预言机输入是手写的已选路径和 site 成本，使用 Python 整数计算数学费用，独立比较 i64 上界。
它不导入生产规则或未来的块分析器。对于总成本 C≥2，C−1 在预算首先不足的 site 失败，C 恰好完成，C+1 剩一单位。
这些轨迹供后续插桩验收比对。
