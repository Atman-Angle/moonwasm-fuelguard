# join-span-compact-v1 布局

通过 `--codegen join-span-compact` 显式选择。本布局的计费、分段和诊断遵循
[fuel-v1.2 边界表](fuel-v1.2.md)，Stack 预算沿用 `stack-v1`。CLI 和 manifest
使用单独的布局标识 `join-span-compact-v1`。既有布局的产物和选择方式继续可用。

## Fuel 编码

内联静态扣费仍只执行一次 `i64.const W`。失败分支的 profile 把总费用 W
放在低 7 位，按源站点顺序排列的三位权重放在高 57 位。短 span 可以用更短的
有符号 LEB128 表示。失败回放用掩码取 W，用无符号右移取权重，随后恢复
预扣前余额，按原算法扣费并报告首个不可支付站点。

以所有含 `loop` 的函数为根，对原模块的直接调用和间接调用做可达闭包。
间接调用保守纳入活动表中所有 `ref.func` 和函数索引目标。可达的宿主调用
也把导出的 guest 函数加入闭包，以覆盖宿主重入。闭包之外的非空计费函数
在 span 起点传入首站点和 profile，调用共享的静态扣费函数。共享函数直接
读写全局余额，余额不足时调用同一个回放 helper。闭包内的函数继续走内联。
缓存余额的发布、调用后重载和动态费用检查仍按同一规则执行。

## Stack 编码

Stack 使用 `join-span-cached` 的打包序列和启用范围。打包检查用两条符号位
判断预算不足，Stack 优先于 Depth，非叶调用失败时恢复预留量。超出打包范围
时使用两个 i64 计数器。两种 Stack 缩减试验的采样和撤回依据见
[S28 证据](../evidence/S28.md) 里的 A17 试点。

所有 helper 均后追加，原有导入、函数和全局量索引保留。管线逐阶段验证，
并审计追加索引、局部变量及函数体。生成代码的 `A ≤ C` 审计包含共享扣费、
回放及其实际调用链。helper 不产生独立的预算预留事件。
交付校验从实际 Wasm 的内联失败分支和共享调用重建原指令站点及 span 表。

## join-span-compact-v2

`--codegen join-span-compact-v2` 显式选择第二版。它沿用 `fuel-v1.2`、
`stack-v1` 和 `diagnostics-v1`。CLI、产物标记和 sidecar 都记录
`join-span-compact-v2`，`--codegen join-span-compact` 继续选择第一版。

- 带本地 Fuel 缓存的函数在静态扣费后将缓存视为待发布。发布成功和调用后重载
  都使缓存与全局余额一致。同一直线序列内，已有一致性保证时可省去再次发布。
  结构体入口和汇合处按待发布处理，原生陷阱、调用与函数出口仍在需要时发布。
- 打包 Stack 布局在同一调用帧中记住已通过检查的最大直接被调帧费用。该检查
  也证明至少还有一单位深度。正常返回恢复调用者的计数，因此在这个检查支配的
  路径上，下一直接调用若费用不高于该值，重复检查必定成功。非叶调用仍实际预留
  和归还相同的 `C` 与深度。进入子结构可以携带已知下界，子结构中新增的证明
  不传回外层或其他分支。间接调用仍由目标 wrapper 检查。计数超出打包范围时，
  沿用逐次检查的双 i64 计数器。

第二版是显式选择的调优候选。实测和门禁状态见
[S29 后续实验](../evidence/S29-autoresearch.md)。
