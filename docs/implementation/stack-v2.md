# stack-v2 · 31 位栈配置域

[生产规格 v4 §2.2](../14_FuelGuard生产规格_v4.md#22-stack-height-limiter) 要求
栈单位上限、调用深度上限和共享栈成本 C 均在 `1..=2,147,483,647`。
CLI 和 `StackConfig::new` 在解析配置时拒绝范围外的上限。插桩计划在生成
Stack 指令前检查原函数的 C，最终布局审计同时检查生成辅助路径的 C 以及 A ≤ C。
抽象单位、基础帧成本和 v128 的 16 字节计入规则沿用 [stack-v1](stack-v1.md)。

生成的所有 StackPass 产物使用同一打包路径。入口包装器首次执行时，把初始
栈单位放入低 32 位、初始深度放入高 32 位，并将原深度全局置零作为初始化标记。
初始上限保留在产物的全局声明中，供 runner 实例化前检查。调用预留扣除
`(1 << 32) + C`，检查低位符号来判定栈不足，再判定深度不足。正常返回恢复预留。
闭合叶调用及已有支配检查复用的路径按原模板维持相同的预算判定。

## 迁移

产物 marker 和 manifest 记录 `stack-v2`。旧 `stack-v1` 产物仍可配合同版本
清单验证，并可由支持其既有认证范围的 runner 读取。迁移时用未插桩原件和
31 位范围内的配置重建。Fuel 模型版本和 `diagnostics-v1` 的 code/site 布局
独立于此版本变化。
