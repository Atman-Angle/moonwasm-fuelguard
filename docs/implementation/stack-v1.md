# stack-v1 抽象栈成本

每个标量或受支持引用占 1 个抽象单位，v128 占 2 个单位。按 8 字节粒度区分值宽度，所以 v128 按 16 字节宽度计入。单位和固定帧开销用于 FuelGuard 的预算比较，不对应物理引擎栈字节。固定帧开销为 8 个单位。函数自身上界由参数、声明结果、local、可达操作数峰值和固定开销相加得出。声明结果单列预留，以覆盖跨调用返回值存放。

## 实际布局 A

原模块和最终 Fuel/Growth 模块都先经过 Wasm 验证。分析器遍历 typed operand 状态。块入口使用签名参数和不可弹出的外层前缀，条件分臂分别计算。分支对环头与结构出口分别建模。已验证的不可达路径满足多态栈规则，不进入运行期操作数峰值。普通指令借用已锁定 Starshine 验证器的类型效果。它只接收足以覆盖该指令输入的后缀，调用使用目标签名长度，避免反复拷贝整个操作数栈。

对每条调用边区分原函数和追加函数。原函数调用是下一次逻辑预算预留的边界，当前函数的完整 A 在调用期间保留。生成代码按无环图从叶子计算。顺序或互斥路径取最大，嵌套存活帧相加。生成 wrapper 调用原函数时，wrapper 的存活成本留在其入口路径，原函数在自己的预算边界另计。start、export 和静态表中出现的生成函数单列入口行。间接调用保守考虑固定表中的全部可能目标，记录给发出调用的原路径。外部入口按入口行使用成本，间接入口按调用者的辅助峰值使用成本，同一路径不重复预留这两项。实际生成图如果存在递归环、未知指令或无法解析的间接表则构建失败。

## 统一预算 C

C 从原模块 typed frame 和版本化模板约束推导，与候选的实际 A 独立。设 S 为原模块任一函数的参数与结果单位总数的最大值。

| 模板预留 | 单位 | 覆盖范围 |
| --- | ---: | --- |
| 原函数新增 local | 8 | 燃料快照、动态长度和 Stack 临时量 |
| 原函数瞬时操作数 | 16 | 内联比较、扣费、诊断及 helper 参数 |
| Growth helper | 32 | 原始参数与 site、资源检查、动态计费及自己的帧 |
| 共享 charge helper | 32 | P1 或 P2 的 cost/site 参数及冷路径 |
| 入口 wrapper | 32 + 2S | wrapper 固定开销、参数和返回值的两份空间 |

最保守路径同时预留 growth、charge 和一个入口 wrapper。原函数的 C 为原帧加 8、16、64、32 + 2S。纯生成 helper 行上限为 64。生成入口行上限为 64 + 32 + 2S。对每一行检查 A ≤ C，超出拒绝产物。未来模板通过相同审计，新增帧超过版本约束时须重设模型或调整布局。S10 的实际代码证据来自 P0 Fuel/Growth 产物及合成 wrapper，P1 的实际生成帧和子调用计入 [S19](../evidence/S19.md)，P2 由 S20 验证。

`PassResult::stack_layout()` 提供原帧、最终帧、辅助峰值、函数索引和 C/A。CLI `--stack-layout` 打印同一验证结果。S11 使用同一 C 做调用前预留并对真实入口包装的 A 执行审核。[S10 分析证据](../evidence/S10.md) · [S11 改写证据](../evidence/S11.md)
