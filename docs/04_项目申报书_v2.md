#### 项目简介

MoonWasm FuelGuard 是使用 MoonBit 开发的 WASM 构建期资源预算工具。项目面向 `moon build --target wasm` 生成且符合支持清单的模块，计划实现基于指令权重的块级计算计费、完整的 Stack Height Limiter，以及内存/表容量限制，并以 Wasmtime 和 Linux wasmoon 验证插桩前后的语义与资源控制效果。开发者通过插桩库或命令行完成“编译 → 设置预算并插桩 → 执行 → 查看结果或超限原因”的流程。输出模块不新增 import，插桩核心与宿主运行时解耦。

**痛点与生态位**：自动化测试和插件执行中的失控循环、深递归、大栈帧及持续内存增长，可能长期占用执行资源。开发者需要明确预算、终止原因和复现方式。FuelGuard 将预算检查写入模块，使资源控制可以随构建产物交付，并与 MoonBit 的构建、CI 和测试流程集成。

**竞品与优势**：wasm-instrument、Binaryen 等项目提供了成熟的计费与插桩思路，starshine 提供 WASM 解析、校验和编码基础。FuelGuard 在此基础上，用 MoonBit 自行实现加权计费分析、调用栈保护、增长控制及代码生成，形成可集成到 MoonBit 构建与测试流程的资源预算工具。项目以版本化费用模型、独立运行时验证和性能报告说明支持范围与实际效果。

#### 预期使用场景

1. **WASM 测试 / 模糊测试 / CI**：对真实 MoonBit 产物设置计算、栈和内存预算。预算充足时保持原程序结果，超限时按约定终止，报告预算、原始函数/指令位置及复现信息。这是首版主要场景。
2. **Agent / 插件资源预算**：在构建期为插件写入资源上限和导入允许列表，宿主加载模块并接收超限诊断。宿主同时负责文件、网络、导入函数内部行为及墙钟时间限制。
3. **构建期资源配额**：为不同资源档位生成带固定预算的 WASM 产物，记录费用模型版本和文件哈希，便于部署与问题复现。同一实例的预算累计消耗，独立执行可创建新实例。

#### 核心功能范围

- **Pass 管线 + 库 API**：提供模块分析与插桩计划，按 Fuel → Growth → Stack 执行改写。每个 pass 后校验，编码前再次校验，输出不新增 import。第三方 Pass 作为实验性扩展接口。
- **Fuel/Budget Pass**：发布版本化指令权重表，静态费用按实际控制路径形成计费块并合并扣费，对内存复制、填充和增长按请求长度追加动态费用。同样迭代次数下，长短循环体及不同操作具有相应费用差异；函数入口/循环固定扣 1 仅是早期原型。使用检查溢出的 i64 预算，超限写入诊断后 trap；费用表示计算配额，不等同于 CPU 时间。
- **Stack Height Limiter**：在原始调用前预留抽象栈预算并检查逻辑深度，正常返回释放，覆盖直接调用、间接调用、导出及 Wasm start 入口。成本含参数、局部变量、操作数栈峰值、帧常量及生成 helper/wrapper，既限制深递归，也覆盖浅调用的大栈帧；单纯入口深度计数不能替代该能力。各布局的成本上界在构建期核验，已覆盖的 helper 不再增加现场检查。
- **Growth 与导入控制**：检查 memory/table 初始容量和增长上限，以无符号差值避免容量回绕，支持精确导入允许列表。初始超限拒绝，运行期超限 trap；上限内保留原始 grow 的底层失败返回值，已收动态费用不退款。
- **运行适配与诊断**：产品运行入口支持 Linux/WSL wasmoon，Wasmtime 用于独立互操作测试。诊断包含失败类型和原始指令位置，trap 后废弃实例，初始化诊断不可读时明确报告。
- **正确性保障**：真实 MoonBit 产物、独立计费预言机、原/插桩差分、控制流边界和生成/变异语料共同验证。编码后使用独立工具检查，不支持输入明确拒绝。
- **CLI/工程**：交付 wasm/moonx 兼容的 `instrument`、Linux `run`、确定性产物说明、性能报告、示例、迁移说明及 mooncakes 包。
- **明确不做与首版边界**：完整安全沙箱、源码覆盖、调用追踪与 profiling 不在首版交付范围；支持清单限定 wasm32、最多一个非共享 memory 和一个 table。间接调用限内部固定 funcref table，externref table 增长单独验证。GC、component model、memory64、线程、尾调用、异常处理、SIMD、可变或可逃逸 funcref table、Windows 原生及浏览器适配均在首版范围之外。

#### 预期验收产物

- **包与工具**：交付 `Atman-Angle/moonwasm-fuelguard` 库、可通过 moonx 运行的插桩入口及 Linux runner，完成干净环境安装和真实 MoonBit 产物复现。
- **资源控制演示**：展示同迭代次数的长短循环体费用差异，有限计算提高 Fuel 后完成，无限循环在有限 Fuel 下终止；深递归与浅调用大栈帧分别受控；memory/table 初始及增长边界按规则拒绝或终止。预算充足时结果一致，受控失败带原因和原始指令位置，并与程序自身 trap 区分。
- **差分与验证**：至少 60 个具名确定性用例，其中至少 20 个控制流或栈边界用例，覆盖至少 3 类真实 MoonBit 工作负载。另运行至少 10,000 个不同的有效生成/变异样本，保存最小失败样例和复现种子。
- **跨运行时证据**：同一份插桩产物在 wasmoon 和 Wasmtime 中实际执行，分别比较插桩前后的返回值、输出、选定内存状态和原生 trap；在严格确定性子集中比较相同预算下的受控终止 code/site 及输出前缀。使用独立计费预言机及独立二进制校验，不用“能加载”替代执行验证；WASI、NaN 和底层分配差异单列。
- **性能与体积**：报告 Fuel-only 与完整保护的生命周期、热调用、构建、体积及内存数据，启动阶段的业务计算计入生命周期。默认布局在调优集选定后冻结，独立验收集只确认达标。工程目标为各引擎、各适用计时窗口分别时间比几何平均不超过 2 倍，逐负载中位数及 p95 时间比不超过 3 倍，按 95% 置信区间上界判定。完整保护后的 Wasm 文件按原始模块大小分档验收。原件至少 10 KiB 的代表模块，插桩后与插桩前的体积比不超过 3 倍。原件小于 10 KiB 的代表模块，Wasm 文件新增不超过 15 KiB。诊断清单文件的体积单独报告。以上门槛以独立验收集的复测结果判定。
- **文档与报告**：交付 README、示例、版本化费用表、诊断映射、Apache-2.0 许可证及依赖说明。验收结果绑定源码版本、配置、原始数据及输入输出哈希，记录实际通过、失败和未执行项，保证报告可复核。

#### 原创 / 参考说明

- 本项目为**原创实现，非移植项目**。计费分析、调用栈保护、增长控制和内联/共享函数/混合布局均由 FuelGuard 使用 MoonBit 自行实现。
- 参考 [wasm-instrument](https://github.com/paritytech/wasm-instrument) 的 gas/stack 思路、[Binaryen](https://github.com/WebAssembly/binaryen) 的结构化处理方式，以及 [Wasmtime](https://docs.wasmtime.dev/) 的执行与验证实践。参考项目仅提供设计依据。
- 当前使用 starshine 0.3.0 提供解析、校验和编码。计划接入 wasmoon 执行适配，并使用 Wasmtime 与 wasm-tools 进行独立测试。
