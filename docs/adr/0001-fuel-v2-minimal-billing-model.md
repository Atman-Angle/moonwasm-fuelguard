# fuel-v2 最小计费模型：span 首指令诊断与不设上限的直线合并

申报书只要求失败诊断"包含失败类型和原始指令位置"，不要求 span 内逐指令回放；fuel-v1.2 为"首个不可支付指令"维护的 57 位 profile 权重编码把直线合并上限锁死在 19 条，是 A19 体积超限的主要放大器。fuel-v2 决定：失败 site 为触发预扣的计费块首条源指令，删除 profile 与回放；直线合并不设上限，分段仅由控制流结构决定。预扣只会更早触陷、不会更晚，语义安全；代价是失败定位粒度从指令级变为计费块级。

备选方案（保留逐指令精度、只压缩编码）被否决：体积收益只有约三分之一，F1 无法接近 2× 门槛。
