## 一、赛事定位

本赛事以 MoonBit 编程语言及其工具链为基础，面向所有开发者群体（不限学生或社会人士），鼓励参赛者利用 AI 工具与 MoonBit 完成各类开源库、生态包、开发工具和示例工程的设计、移植、实现与完善，共同推动国产开源基础软件生态建设。

本期赛事在持续支持新生态项目建设的基础上，进一步鼓励新项目和处于活跃维护状态的旧项目参与季度生态优秀项目评选。赛事希望通过“新增生态能力”与“提升已有项目质量”并行的方式，推动 MoonBit 生态从项目数量积累逐步走向可用、稳定和可持续维护。

---

## 二、赛事宗旨

MoonBit 作为面向 AI 时代的新一代编程语言和开发者工具链，具备现代类型系统、统一工具链、多后端支持以及面向工程化开发的设计基础。为了进一步降低开发者参与 MoonBit 生态建设的门槛，本赛事将重点聚焦“开源生态库建设”，鼓励参赛者参与生态共建。

本赛事强调项目真实可用、边界清晰、文档完整、测试可运行、后续可维护。参赛者可以从其他成熟语言生态中选择合适的开源库进行 MoonBit 移植，也可以围绕 MoonBit 生态中的实际需求设计原创库或示例项目。赛事鼓励合理使用 AI 工具完成代码生成、接口设计、测试补全和文档撰写，但最终成果应体现参赛者对项目目标、技术路径、质量边界和开源合规的理解与把控。

本赛事希望通过广参与、可验收、可展示的方式，形成一批真正能够被 MoonBit 开发者使用、学习和继续演进的生态项目，为国产开源生态积累更多基础组件和实践经验。

## 三、参赛对象与参赛形式

### 3.1 参赛对象

本赛事面向所有对 MoonBit、AI 编程、开源生态、基础软件和软件工程实践感兴趣的开发者群体（不限学生或社会人士）。

### 3.2 参赛形式

本赛事支持个人或团体参赛，报名时仅需填写并提交一份报名表单即可。如以团体形式参赛，团队人数不超过3人，由队长或团队指定代表统一填写报名信息并提交。

如团队参赛项目获得奖金，相关奖金将统一发放至队长或团队指定代表账户，具体分配方式及比例由团队成员人数平均比例分配。赛事组不承担因奖金分配产生的任何争议、纠纷或相关责任。

每位参赛者原则上提交一个参赛项目，并在申报时选择以下一种参赛方向：

1. 新生态项目建设，报名此方向并通过验收后，将自动参与季度优秀社区项目评选
2. 继续维护已开启的项目并参与季度优秀社区项目评选

## 四、项目方向

### 4.1 新项目方向

新项目可以是原创实现，也可以是对其他成熟语言生态中优秀开源库的 MoonBit 移植或重写。

鼓励参赛者参考 Rust、Go、Python、OCaml、Java 等成熟语言生态，根据 MoonBit 当前发展阶段选择具有实际需求的项目进行实现。

新项目不得直接重复 MoonBit 生态中已经存在且功能高度重合、维护状态良好的成熟项目。请选手在申报前通过浏览 mooncakes.io 网站或者使用比赛助手 SKILL确认自己的选题没有和已有项目重合。

如拟建设方向已经存在相关项目，应优先评估是否可以通过参与已有项目维护、功能扩展或协作开发的方式完成生态贡献。如有明确理由要建设社区中已有项目的类似项目，应在申报书中予以明确说明。

### 4.2 季度优秀社区项目评选方向

对于已经参与 MoonBit 生态建设的开发者，具备一定可用性的 MoonBit 生态项目，选手可以继续维护自己的项目并报名参加季度优秀社区项目评选。该方向要求主要贡献者必须是参赛者本人，不要求项目是赛期内新建项目，也不要求是个人项目（允许多位贡献者）。参赛者可围绕现有项目开展持续维护与升级，包括但不限于：

- 新增重要功能或完善已有功能；
- 修复 Bug，提升项目稳定性、兼容性与性能；
- 适配 MoonBit 最新版本、标准库或工具链变化；
- 完善测试、文档、示例及工程化能力；
- 优化 API、代码结构及用户体验；
- 根据社区反馈持续迭代，提升项目实际使用价值。

该方向目的是为了鼓励社区开发者继续维护自己已开发的项目，并将之维护至优秀水平。

## 五、比赛流程

### 5.1 新项目方向

#### 阶段一：项目申报（即日起-9月30日24点）

参赛者需通过飞书问卷报名入口提交参赛项目信息进行报名，报名后请加入赛事通知微信群。报名入口、申报模板及提交截止时间以赛事群为主。

[图片]

[图片]

问卷中要求填写一份项目申报书，问卷提交后，赛方会对申报书进行审核并发送结果通知邮件。若通过，该项目即可启动，赛方会同时发放第一阶段激励奖金；若不通过，邮件会说明拒绝原因，选手可以调整项目内容后，通过修改问卷继续申报。

申报书内容包括：

1. 项目名称；
2. 项目简介；
3. 项目方向，通用性说明；
4. 至少3个完整的预期使用场景；
5. 拟实现的核心功能；
6. 是否为原创项目、移植项目或参考已有开源项目；
7. 如为移植项目，需说明参考项目名称、来源链接和许可证；
8. GitHub 仓库链接，含有不少于 10 个有效commits，不得通过无意义拆分、空提交或重复提交满足次数要求。

具体的选题指导可参考附录一。选题和撰写申报书的审核原则是确保选手对自己将要建设的项目有充足的理解和实现思路。在撰写并提交申报书之前，务必确保：

1. 该题目真实反映了客观需求，完成该选题的任务可以切实解决现实问题；
2. 拟采用的技术方案是目前最优或最合适的，而非陈旧的、粗糙的解决方案；
3. 当前类似的项目在 mooncakes.io 上并不存在。

申报书务必人工撰写，篇幅控制在一页 Markdown 内，无须展开大篇幅的背景介绍。明显包含 AI 套话或没有体现选手对选题有深刻认识的申报书会被在审核阶段被驳回。

建议直接回应以下核心问题：

1. 项目价值与生态定位

   你观察到了哪些具体的痛点？为什么在 MoonBit 当前的生态下，这个项目非做不可？

   如果存在“缺口”，项目将补齐怎么样的生态位，这个生态位重要在哪？

   如果存在“竞品”，你实现的项目“优势”体现在哪，它为什么重要？

2. 交付范围与工程边界

   你觉得这个项目能做到或者应该做到什么样的程度？你最终打算交付哪些具体功能？

   是否存在哪些内容是明确不做的？

3. 实现路径与技术理解

   实现这个项目有哪些常见的路径？你想好自己的实现路径了吗？

   完成实现需要哪些能力？你有没有一些独到的理解？

申报样本可参考附录二：项目申报书样本。

符合条件的项目可获得 150 元 / 项目 的启动支持。

启动支持用于鼓励参赛者尽快完成项目初始化、工程搭建、AI 工具使用、基础样例和早期代码探索。启动支持不代表项目已通过最终验收。

#### 阶段二：项目开发与社区活动（即日起-9月30日24点）

参赛者可在开发周期内持续推进项目。赛事组将根据实际情况提供以下支持：

- MoonBit 快速开始指南；
- 项目模板仓库；
- 推荐项目方向清单；
- 常见问题答疑；
- 线上宣讲或高校专场分享；
- 社区答疑渠道；
- 优秀项目阶段性展示；
- MoonBit 工程最佳实践说明。

赛事鼓励参赛者在开发过程中保持公开、连续、可追踪的工程记录，包括工单及合并请求、提交记录和更新日志等。

#### 阶段三：项目验收（即日起-9月30日）

赛事组将根据项目完成度、工程质量、文档质量和开源规范进行审核。比赛启动时间起，项目组开始评选入围线下参与展示的项目名单。

申请完成支持的项目应满足以下要求，上传到 Github

1. 项目以 MoonBit 为主要实现语言；
2. GitHub 仓库公开可访问，提交记录清晰；
3. 源代码结构清晰，能够完成声明的核心功能；
4. 提供 README，说明项目目标、安装方式、使用方法和示例，并可复现；
5. 使用持续集成工具并且覆盖检查、构建、测试流程；
6. 提供至少一个可运行示例或最小使用样例；
7. 提供完整测试，覆盖核心功能路径；
8. 发布到 mooncakes.io；
9. 采用 OSI 认可的开源许可证；如参考或移植其他开源项目，应符合原项目许可证要求。

通过验收的项目可获得 350 元 / 项目 的完成支持。

启动支持与完成支持合计为 500 元 / 项目。该基础激励旨在鼓励更多开发者完成可用的 MoonBit 生态项目，与最终优秀作品奖励不冲突。

#### 阶段四：最终结果公示和优先项目展示

在基础验收之后，赛事组将根据项目完成度、对 MoonBit 开源生态的贡献、工程质量等维度综合评估，从通过验收的项目中遴选一批具有代表性的优秀项目，进入季度优秀社区项目评选。

### 5.2 季度优秀社区项目评选方向

对于每月的已通过验收的新项目和参与季度优秀项目评选的报名的社区项目，每季度会进行评选。

如果要报名参与季度评选，参赛项目的主要贡献者必须是参赛者本人（允许有其他贡献者）。

具体奖励机制参见赛程第六章。

## 六、激励机制

本赛事激励分为两类：基础共建激励和季度/半年度优秀作品奖励。

### （1）基础共建激励：新生态项目建设

申请启动支持的新项目，应完成基本项目初始化，并提交清晰、可执行的项目 Proposal，包括项目目标、核心功能、技术路线及预计交付成果。

赛事组审核认为项目具有明确生态价值、合理工作范围及实际完成可能性的，可获得 150 元启动支持。

申请完成支持时，应完成申报阶段约定的主要功能，形成公开、可运行、可复现的项目成果，并满足赛事规定的代码、测试、文档、持续集成及开源规范要求。

通过最终验收后，可获得 350 元完成支持。

#### 基础激励限制

以下情况不视为有效生态贡献，赛事组有权不予发放基础共建激励，已经发放的启动支持可视实际情况取消后续奖励资格：

- 重复提交本人此前已经参加赛事并获得支持、且无明显新增贡献的项目；
- 对已有项目仅进行少量格式调整、文字修改或机械性更新；
- 通过拆分 Commit、空提交等方式制造虚假开发记录；
- 提交与现有 MoonBit 生态项目高度重复、且无明显新增价值的项目；
- 大量复制、机械生成或简单转换代码，无法说明核心实现和实际贡献；
- 维护类项目未完成申报 Proposal 中的主要目标；
- 项目无法运行、无法复现或与申报内容明显不符；
- 其他经赛事组认定不存在实质生态贡献的情况。

对于曾参与此前 MoonBit 开源赛事的项目，如本次存在新的、独立且可验证的开发或维护成果，仍可重新申报。赛事仅对本届比赛周期内新增的有效贡献进行评估和激励，历史成果不重复计算。

### （2）季度/半年度作品激励：既有生态项目维护与升级

参赛项目应以本届赛事期间新增的有效贡献/维护作为主要验收依据，不以项目历史代码量或既有完成度作为本届支持和评奖依据。赛事组将综合评估本阶段新增工作量、技术价值、完成质量及项目实际影响，对符合要求的项目予以邮件通知和季度奖励。

- 推荐奖励可与基础共建激励、优秀作品奖励叠加获取，不受项目数量限制。

## 七、开源与成果提交要求

参赛项目须以开源方式提交，并满足以下基本要求：

1. 项目须在 GitHub 或赛事组认可的平台公开发布；
2. 仓库须包含完整源代码；
3. 仓库须保留合理开发历史记录；
4. 仓库须包含 README 文档；
5. 项目须选择 OSI 认证许可证；
6. 如项目移植或参考其他开源项目，应在 README 或专门文档中注明原项目名称、链接、许可证和参考范围；
7. 项目须遵守第三方依赖及参考项目的许可证要求；
8. 项目不得侵犯他人知识产权，不得提交未经授权的私有代码、闭源代码或商业代码；
9. 如项目包含生成代码、测试数据或样例文件，应保证其来源合法合规；
10. 项目通过验收并参与展示的，参赛者同意主办方在保留作者署名的前提下，用于赛事宣传、官网展示、社区文章、技术分享和生态推广。

参赛者保留项目的著作权及开源项目署名权。赛事支持与奖励不构成主办方对项目著作权、商业权利或独占使用权的购买。

## 九、违规处理

参赛者应遵守开源规范、学术诚信和基本工程伦理。出现以下情况的，赛事组有权取消项目立项、验收资格、激励发放资格或获奖资格：

1. 提交虚假个人信息或项目信息；
2. 抄袭、冒用、盗用他人项目成果；

- 使用场景过于特殊的。例如只能生成海报的排版软件、只能分析一种特定格式的审计工具

- MoonBit 官方软件，比如 mooncakes.io 的发布审计工具、moon-fmt 的个性化实现等，除非对自己的作品质量有绝对把握

## 附录二：项目申报书样本

### moon_elk 项目申报书

#### 基本信息

- 项目名称：Moon ELK：Eclipse Layout Kernel 的 MoonBit 移植
- 参赛者：布丁大魔王
- 联系方式：1234567890
- GitHub 仓库链接：https://github.com/moonbit-community/moon_elk.git
- 项目方向：MoonBit 图布局基础库 / 可视化基础设施
- 是否为移植项目：是

#### 项目简介

Moon ELK 计划将 Eclipse Layout Kernel（ELK）的核心图布局能力移植到 MoonBit 生态，为流程图、数据流图、状态机、建模工具、IDE 插件、低代码编辑器和可视化分析工具提供可复用的自动布局引擎。项目面向需要在 MoonBit 中构建或处理图结构的库作者、工具开发者和应用开发者，提供 ElkGraph 数据模型、JSON 导入导出、布局选项解析、布局算法调度以及多种常用布局算法的 MoonBit 实现。

这个排版引擎功能非常全面。传统的跨语言使用方法是在项目中嵌入一个 JS 虚拟机，然后在虚拟机中运行 ELK 的 JS 版本 elkjs。但这种方式非常昂贵，性能无法得到保障，还要处理跨语言数据验证问题。将这个项目移植到 MoonBit，利好所有需要使用排版引擎的软件开发，而且可以修复一些在 Java 或 JS 版本上难以修复的 bug，以及提供日后优化引擎本身的可能性。

#### 核心功能范围

- 提供 ElkGraph 风格的图模型，支持节点、边、端口、标签、层级节点和布局属性；
- 支持 ELK JSON 格式的导入、导出和 pretty print，便于与前端渲染器或现有 ELK 工具链交换数据；
- 提供统一布局入口 new_elk_engine().layout(...)，支持按 elk.algorithm 分发算法；
- 支持 Layered、Force、Stress、Radial、MrTree、RectPacking、Spore、Fixed、Box、Random、Vertiflex 等布局能力；
- 支持基础布局选项解析，包括方向、间距、端口约束、节点尺寸、边路由和算法特定配置；
- 提供算法元数据、服务注册、布局校验和调试辅助模块；
- 提供 Graph Text / ELK Text 相关解析和转换能力的基础实现；
- 提供与 elkjs / ELK 参考实现对照的差异测试、随机用例和迁移记录；
- 提供 README 示例，覆盖 JSON 布局、图模型构建、JSON 导入导出和算法选择。

#### 预期验收产物

- moonbit-community/moon_elk 库，可直接通过 moonx moonbit-community/moon_elk 使用 CLI，或者通过 moon add moonbit-community/moon_elk 在 MoonBit 项目中使用其 API；
- 支持完整的 ELK 功能。对于任意的 ELK JSON 输入，能输出和 ELK 0.12.0 完全一致的排版结果；
- 自带差分测试工具和测试记录报告；
- 性能优于 ELK，对于任意输入，排版时间均超过 ELK 0.12.0；

#### 移植或参考说明

- 原项目名称：Eclipse Layout Kernel（ELK）
- 原项目链接：https://github.com/eclipse-elk/elk
- 原项目许可证：Eclipse Public License 2.0
- 本项目许可证：Eclipse Public License 2.0

与原项目相比，本项目会做以下简化和重新设计：

- 使用 MoonBit 原生包结构、类型系统和测试方式组织代码，而不是复刻 Java 插件工程结构；
- 优先实现可在 MoonBit 中独立运行的核心布局能力，弱化 Eclipse UI、OSGi、SWT/JFace 等桌面插件依赖；
- 对 Graphviz、libavoid、disco、topdownpacking 等当前暂不完整支持的算法保留兼容入口和错误行为，作为后续扩展范围；
- 对 Java 异常、集合类型、继承层级和服务发现机制进行 MoonBit 化改写；
- 以 JSON 输入输出和 MoonBit API 为主要交付接口，方便接入 Web、CLI、IDE 和可视化渲染场景。
