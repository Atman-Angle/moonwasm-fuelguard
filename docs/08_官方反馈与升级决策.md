## 1. 反馈事实

本次初审未通过；反馈指出函数入口/循环粗粒度 Fuel 难以反映计算开销，缺少调用栈高度保护，建议指令权重或基本块计费、Stack Height Limiter、明确资源边界，以及 Wasmtime 等独立运行时的互操作测试。邮件允许在 2026-11-30 前补充材料并重新提交审核，不构成通过承诺。

## 3. 替代的旧决策

- 函数入口和循环各扣 1 仅保留为原型现状，不能作为 v3 费用模型。
- stack-height guard 从排除项变为生产核心；单纯调用深度不够。
- Wasmtime 从排除项变为必需验证工具；产品 runner 仍是 Linux wasmoon。
- 不再保留 wasm5 候选验证路径，也不扩大 Windows native/浏览器支持。
- Fuel→Guard 改为 Fuel→Growth→Stack，Stack 成本覆盖生成代码。
- 不新增 import、逐 pass 校验、编码前校验和宿主解耦继续有效。
- 原索引保持稳定，但 export/start/element 引用允许有计划改写；不允许借此绕过引用语义测试。
- 历史“≤3x 软目标且不阻塞”改为完整保护硬性发布预算；阈值是工程目标，不是测量结论。

## 4. 性能决策纪律

用户要求性能最好的生产实现。当前没有证据证明某一种代码布局在所有引擎上最优，因此采用正确性先行、冻结语义、候选对照测量的决策过程。不得删除保护、跳过 validate、忽略完整保护开销或改变超限位置换取漂亮结果。

不宣称超过成熟工具的整体能力。额外价值定位为 MoonBit 工具链集成、明确受支持范围、预算语义及可复现验收。费用模型不是 CPU 时间模型，静态 manifest 不是安全证明。

## 5. 尚待证据解决的问题

真实 MoonBit 产物与 production-v1 的兼容性；栈包装/模板成本是否保守；认证运行时原生栈余量；完整保护在目标负载上的开销。各项结论必须通过任务和验收记录更新，不能仅通过修改状态文字关闭。

## 6. 架构对抗审查后的规范修订

本轮审查对象为目标架构，第一版代码缺失不作为目标设计缺陷。已将以下规则写入05/06/09/12并同步任务计划与申报书：

- 统一预算成本C(f)与各布局实际上界A分层，在构建期核验A<=C；互斥/顺序辅助路径取峰值，同时活跃帧相加，helper不新增预算事件或逻辑深度。
- 共享语义计划、候选结构计划、最终StackLayout依次冻结，最终成本分析不反向改变签名/索引结构。
- canonical计费块允许合法合并，所有布局复用；不默认逐load/store插入额外检查。补齐栈/深度、动态溢出和入口的诊断顺序。
- 调优阶段冻结默认布局，独立验收集不参与择优；性能包含core start业务及适用热调用窗口，不能以空调用漏测主计算。
- 三类真实负载前移到支持范围调查；原生栈上界针对受管代码和入口余量，以宿主履约为前提，不扩大任意host内部保证。

以上为规格修订完成，相关实现与性能门禁仍未执行。保留P0/P1/P2优化路线、块级收费和逐阶段校验；不承诺通过修改申报文字即可消除审核风险。

## 7. S01 执行后的支持范围决策（2026-11-10）

S01 已构建并实测四个真实产物：本仓库 hello 基线，以及 `moonbitlang/x@0.5.7` json5（数据解析）、`bobzhang/lisp_interpreter@0.1.4`（解释器递归）、`moonbitlang/x@0.5.7` crypto SHA-256（计算密集）。证据见 [S01](evidence/S01.md)，冻结结果见 [支持矩阵](implementation/support-matrix.md) 与 [环境锁定](implementation/environment-lock.md)。

- **SIMD 冲突与决策**：三类真实负载全部发射同一组 16 条 SIMD 指令与 v128 值类型（MoonBit core 字符串/数组例程），`moon build` 无关闭选项。用户决策纳入该观测最小子集，relaxed SIMD 与其余 SIMD 指令仍拒绝。这不是静默扩展：05/06/09/12/07 已同步，S04 权重、S10 v128 栈成本、S16 双引擎覆盖相应扩展。
- **2026-11-18 修订**：申报书（docs/04 第 35 行）为准且不可修改，SIMD 整体收敛为全部拒绝，前述纳入决议作废。费用表、preflight、语料（负载标量重建后重新冻结）与 A15 边界用例同步更新；栈模型 v128 保守计入条款保留为防御性深度。见 S25。
- **生态构建格式冲突**：`gmlewis/json`、`bobzhang/jsonl`、`jinser/json`、`hackwaly/regex`、`Guest0x0/dregex`、`bobzhang/html_parser`、`kawaz/unicodegrapheme` 因自身或传递依赖仍用 `moon.mod.json`，被当前工具链拒绝解析依赖图。未修改第三方源码或手改 vendored 元数据，改用可干净解析的真实包；失败候选与原因全部留档。这是构建格式不兼容，不是插桩支持冲突，也未用容易样例替换目标兼容性。
- **输入上限**：按实测最大值加工程余量给出暂定上限（4 MiB / 4,096 函数 / 4,096 local / 256 嵌套等），标记 PROVISIONAL；S09 实现解码前有界预检，S20 压力测试后冻结，未冻结不得发布。
- **仍未关闭**：Linux 认证环境（本机 WSL 仅 docker-desktop）、wasmoon/Wasmtime 实际版本与执行、栈模板与 v128 上界、完整保护开销。双引擎覆盖全部 NOT_RUN，不得据本文声称生产支持。
