## 1. 产品目标

面向 MoonBit Wasm 的 CI 和确定性测试，提供构建期资源预算插桩：版本化计算计费、抽象栈限制、memory/table 增长限制及可复现诊断。不新增 import，插桩核心不依赖运行宿主。

生产级是验收目标，不是当前状态。性能目标是指定运行时、硬件和负载下经过测量的最佳合格实现；不承诺所有引擎和程序上的全局最优。

性能分析、费用规则、计费块改写、栈保护、增长限制和代码布局由FuelGuard以MoonBit自行实现。外部项目只作研究参考；解析/验证/编码可使用starshine，独立测试可使用外部工具。高性能实现规格见 [12](12_FuelGuard高性能实现方案.md)。

## 2. 交付范围

| 能力 | v3 要求 |
| --- | --- |
| Fuel | 加权计费块预扣、动态长度费用、i64 有界预算、版本化费用表 |
| Stack | 参数/local/操作数栈峰值与帧开销的抽象成本；调用前检查；深度上限作为补充 |
| Growth | memory/table 初始上限与增长检查；保留上限内底层失败返回值 |

| 独立验证 | Wasmtime 测试驱动、独立二进制校验、确定性差分 |

wasmoon 是产品 runner；Wasmtime 是必须的独立验证工具，不引入通用 Host 框架。Windows 可开发和构建 wasm，但 Windows native runner、wasm5、浏览器不纳入生产支持。

## 3. 输入支持契约

生产配置名为 production-v1。每一种特性必须具备解析、验证、计费、栈分析、改写和双运行时测试六项覆盖，才可进入允许表。解析成功不代表支持。第一批支持候选为 wasm32 标量指令、结构化控制流、multi-value、单 memory、单 table、完成动态计费的 bulk memory；SIMD 全部拒绝（2026-11-18 决策，见支持矩阵第 4 节）。逐特性允许/拒绝表、六项覆盖状态与输入上限见 [支持矩阵](implementation/support-matrix.md)。

- 最多一个非共享 memory 和一个 table；GC、component、memory64、threads/atomics、tail-call、异常处理、stack switching、多模块链接均拒绝。
- SIMD 按 2026-11-18 决策**全部拒绝**（申报书 docs/04 第 35 行为准，S01 的最小子集纳入决议作废）：preflight 拒绝全部 SIMD opcode 与 v128 值类型声明，relaxed SIMD 有独立消息；真实负载以自持标量实现去 SIMD 重建。v128 计入条款在栈模型中保留为防御性深度，生产路径不可达。重新纳入 SIMD 须先修订申报书并补齐六项覆盖，不得默许。
- call_indirect 仅支持内部固定 funcref table：拒绝该 table 的 import/export、运行期写入/grow/copy/init/fill 和可逃逸函数引用；active element 引用经包装改写。该限制必须在 CLI 诊断中列出。
- externref table 的增长作为独立覆盖项，引用只作不透明值；引用类型操作逐项允许。不能因支持 externref table.grow 就宣称支持可变 funcref table。
- 生产配置拒绝 imported memory/table 和 exported table；可导出 memory，但宿主不得在执行期间并发修改或扩容。
- host import 禁止重入本实例，宿主内部成本、I/O 和墙钟时间由部署者约束。允许列表不是沙箱。
- 拒绝保留诊断名称冲突、已带本工具插桩标记的输入和未知费用模型。
- 为二进制大小、函数数、local 数和嵌套深度设置显式有限上限；S01 已按四个真实产物给出暂定上限（见支持矩阵第 5 节），边界值在实现阶段通过压力测试冻结并公开，未冻结前不能发布。

冻结支持范围前，先确定至少三类真实 MoonBit 应用负载，记录来源版本、输入、构建选项和产物特性；先在双运行时验证原模块，再随实现验证完整插桩。S01 已选定并构建数据解析（`moonbitlang/x@0.5.7` json5）、解释器递归（`bobzhang/lisp_interpreter@0.1.4`）、计算密集（`moonbitlang/x@0.5.7` crypto SHA-256）三类负载，双运行时执行仍待 S02。支持冲突必须明确处理，不以事后替换成容易通过的样例代替目标兼容性。参数和返回值数量上限也属于受测输入范围。

## 4. 预算语义

### Fuel

费用模型 fuel-v1 发布完整的指令权重表和动态公式。候选权重是工程配额，经微基准校准后冻结，不声称等于 CPU 时间或 Wasmtime 原生 fuel。

静态块成本为原始指令权重之和。只有在正常路径必然一起执行的指令才允许合并；动态操作、调用和可能 trap/产生外部副作用的操作采用保守边界。预算不足在块执行前终止；原生 trap 可能导致已预付但未执行的块尾费用，不退款。

动态 bulk 操作按请求字节数/元素数收费；grow 按请求页数/元素数收费，底层失败不退款。参数求值仅一次。费用算术使用有界 i64，先验证乘加不溢出，再比较剩余额度，最后扣减；禁止溢出回绕。预算范围为 1..2^63-1。

一个实例共享累计预算；不提供运行期 setter。插桩生成代码不重复收取原程序 Fuel，但性能和栈开销必须统计。对同一确定性轨迹，在其他资源限制不变时增加 Fuel 不得更早因 Fuel 终止；不承诺任意非确定程序、原生 trap 或其他限制下的全局单调性。

canonical 分块和 site 是费用模型的一部分，P0/P1/P2 共用同一划分；保守边界不要求每条 load/store 或可能 trap 的指令独立收费。无 trap、无可观察副作用的必经前缀可与块末边界指令合并，具体边界表随模型冻结。不能在同一模型下为某种布局重新切块或移动失败位置。

### Stack

同时限制抽象栈单位与调用深度；函数成本含参数、local、最大操作数栈、保守帧常量及插桩生成代码的开销。调用前预留，正常返回后释放；导出/start/间接调用入口均覆盖。禁止把仅在函数体入口增加深度计数包装成完整 Stack Height Limiter。

抽象栈不是引擎原生栈字节。生产支持需绑定引擎版本和原生栈配置，测出安全范围；用户要求超过已认证范围时 runner 拒绝。trap 后实例废弃，不能恢复运行或重用诊断状态。

栈模型独立版本化。统一函数预算成本 C(f) 覆盖同一模板族中 P0/P1/P2 的最坏受管开销；各布局的静态实际成本上界 A(layout,f) 只用于构建期核验 A <= C，不按布局重新定义用户收费。运行期沿用原始调用边界的常量预留/释放，已覆盖的生成 helper/wrapper 不另设可失败预算点。顺序或互斥辅助路径取峰值，同时活跃的嵌套帧相加；原始调用链的挂起帧继续累计。新模板超出共同上界时拒绝该候选，或升级栈模型并重新验收。

max-call-depth 表示原程序逻辑调用深度：外部进入原函数计 1，原始 call/call_indirect（包括导入调用边界）增加 1，正常返回释放；生成 helper/wrapper 不额外计层，宿主内部调用不由该计数覆盖。候选布局保持相同用户预算事件、诊断和输出前缀。

受管 Wasm、生成代码及入口余量的保守上界须有可审计依据，压力探针只作验证，不能替代上界依据。保证以宿主遵守禁止重入及自身资源约束为前提，不扩展为任意导入函数内部的原生栈保证。

### Growth 与错误

对 unsigned delta 检查 current <= limit 且 delta <= limit-current，禁止 current+delta 回绕。初始超限在插桩阶段拒绝；执行阶段超限 trap；范围内的底层 grow 失败仍返回 -1。资源失败不承诺回滚此前副作用。

同一操作的顺序：已到达块静态费用 → 资源上限检查 → 动态费用检查/扣减 → 原始操作。函数调用按已付静态调用费 → 栈/深度预留 → 调用 → 正常返回释放。该顺序及 trap 优先级是版本契约。

直接调用先检查栈单位（code 4），再检查逻辑深度（code 5），两者通过后才更新计数。间接调用支付静态调用费后保留原生索引/null/类型检查，目标有效才由 wrapper 检查目标预算；不增加重复目标解析。外部 export/start 入口先检查栈和深度，再进入原函数的首个 Fuel 站点。动态费用的数学结果超过 i64 最大值时按该 site 的 Fuel 失败（code 1）处理，检查在溢出运算之前完成。已预留的生成辅助路径不改变上述优先级。

## 5. 诊断与使用

trap code：0 模块自身 trap（仅有可靠实例诊断时），1 Fuel，2 memory，3 table，4 stack，5 depth。保留未知值为无效诊断。start/实例化失败拿不到实例时报告 initialization-trap/diagnostic-unavailable，不能推断为 Fuel 或模块自身错误。

成功路径不逐块记录位置；失败分支写 code、原始函数和稳定 site ID。静态 sidecar 映射 site 到原始指令序号/路径；不承诺 MoonBit 源码行号。诊断 ABI 版本化；宿主是可信使用者，导出的 mutable global 不是防篡改边界。

目标参数（尚未实现）：--profile production-v1、--cost-model fuel-v1、--fuel、--max-stack-units、--max-call-depth、--max-memory-pages、--max-table-elements、--allow-import、--report。生产配置要求为存在的资源显式设上限，禁止静默降低保护等级。

## 6. 发布要求

[09](09_验证与验收计划.md) 的正确性、性能、兼容性和失败处理门禁全部通过，才能称生产支持。申报可以报告阶段成果，但不得把计划写成通过结果。先主场景 CI，Agent/Serverless 是后续使用场景，不扩展本版支持承诺。

不建设通用优化器/SSA、运行时预算修改、UI、托管服务或安全沙箱。第三方 Pass 仍是实验性 API；任意扩展组合不继承内置生产配置的保证。
