# S20 P2 静态混合布局

执行日期为 2026-11-18（北京时间）。依据 [S20 分片](../07_任务分片_MoonWasm_Instrument.md#s20-实现本项目p2静态混合候选)
和 [A16/A18](../09_验证与验收计划.md)。基线为 `b6a4783`，实测工作树逐文件
SHA-256、工具、worker 和 Wasmtime 库的摘要见原始证据的 `environment.json`。

[精确前缀扣费续调](S20-prefix.md) 记录后续候选和测量。

## 规则与来源

P2 按原函数选择模板。无 `loop` 且至少有 **21** 个既有静态计费站点的函数使用
共享 `charge(i64, i32)`，其余使用内联模板。用原函数的静态循环结构近似重复
执行的可能性，把较长的无循环函数用于分摊共享调用的体积开销。阈值按站点数
计算，与指令权重、预算数值、机器和运行时统计无关。

阈值是 S18 冻结调优集 F0–F3 应用中，至少有一个计费站点且无循环的所有函数
的站点数下中位数。计算使用 S19 留存的 P1 sidecar，按 `kind == "instruction"`
分组，排除包含 `opcode == "loop"` 的函数。S19 实测的共享调用运行成本和字节
数下降用于决定静态特征，阈值计算与 P2 正式计时独立。各 sidecar 的输入哈希
匹配冻结清单，输出哈希匹配 S19 归档 Wasm。

| 调优应用 | 有循环的函数数 | 无循环且有站点的函数数 | 组内下中位数 |
| --- | ---: | ---: | ---: |
| F0 hello | 14 | 29 | 14 |
| F1 JSON5 | 76 | 186 | 22 |
| F2 Lisp | 88 | 261 | 21 |
| F3 SHA-256 | 22 | 84 | 18 |
| 合计 | 200 | 560 | 21 |

同一模块至多生成一个共享 helper，并仅在存在共享收费函数时追加。可共享的
原函数使用其原站点 ID 和相同的静态／动态费用。Growth helper 在已有共享
helper 时调用它，其他模块继续内联动态扣费。容量门禁、溢出检查及原生
grow 结果继续按既有顺序处理。生成后从最终 Wasm 的 typed frames 和辅助调用图
重算 A，使用原模块和统一 `stack-v1` 计算 C，构建期逐函数检查 A ≤ C。

`--codegen p2` 用于 `production-v1`。Wasm marker 和 manifest 记录
`p2-hybrid-loop-inline-sites21-v1`，交付验证检查二者匹配。布局沿用 P0/P1
的 Fuel、Growth、Stack 模型及诊断 ABI。

## 独立只读审查

独立子代理使用 `/check` 对当前变更做反例驱动审查，重点覆盖 P2、前置改写、
双引擎编排和证据重放。主代理修复，子代理用正式 S20 构建记录复验。

| 严重度 | 反例与修复 |
| --- | --- |
| P2 | 把最大输入的 P2 CLI 参数换成 P0 参数，同时更新两份日志，旧重放会接受错标的 A20 时间和 RSS。重放现在从冻结用例重建每条 build／validate 命令，拒绝错配。 |
| P3 | 把 F1 P2 sidecar 中的 `fuel-v1` 改为同长度的 `fuel-v0`，旧重放仍接受。现在校验模型、ABI、配置、跨布局站点表及 verify 命令。 |
| P3 | 测试注释将间接调用者的 13 单位辅助峰值归给共享 charge。归档显示 P0 也有相同峰值，检查现覆盖三个布局并按 wrapper 与原目标分别归属。 |

560 个函数和阈值 21。

## A16/A18 正确性

Windows 和 Linux 的 Wasm 单测各通过 97 项，独立 Fuel 预言机通过 9 项。
在相同原模块上运行三布局，确认 20／21 站点边界、恰有 21 站点的循环走内联、
静态及动态精确预算和 ±1、受控 trap 的 code/site，以及 WASI 输出的字节前缀。
双引擎复核了共享 bulk、Growth → charge 嵌套帧和 start／export／固定表目标
的重写。三布局得到相同原函数 C，实际 A 均在 C 内。三个布局的间接调用者均
计入 13 单位 wrapper 辅助峰值，共享 charge 帧计入对应目标函数自己的 A。
首轮测试假定间接调用者的峰值为 0，修正为三个布局共同的 13，并增加编码后
索引断言后复验通过。

同一输入和配置的三次独立 P2 构建给出同一 Wasm SHA-256
`cb204f7b57bc8ba0e08e16de4e6dcdd23ee399be8f05527acb6f4daa1b4ace93`
与同一 manifest SHA-256
`9d71fd26b9a0976a3cbaa486d04be71763ce709ae711a4896064e282fcd531e3`。
验证拒绝交叉布局标签和未知布局；CLI 明确拒绝未知 `fuel-v2`。

生成／变异语料使用种子 `170026`，与 S19 的输入集合 SHA-256 一致。
10,000 份不同输入全部经过独立输入与输出校验、P2 插桩及双引擎执行，
其中 2,727 份核对了受控陷阱。实际命令如下。

