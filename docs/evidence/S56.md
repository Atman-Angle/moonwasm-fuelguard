# S56 · A20 构建内存复测

2026-11-26。使用 S55 的 MoonBit `0.1.20261126`、WSL `FuelGuard-S26` 和冻结语料。在相同 CLI 二进制和 4 MiB 输入上，默认 glibc 配置的两次峰值 RSS 为 1,005,936 和 1,058,212 KiB。移除自定义填充段的诊断副本仍接近 1 GiB，仅保留自定义段的副本约为 170 MiB。解码结束时已观察到 RSS 大幅上升，`/proc/<pid>/smaps` 显示大量 RSS 位于宿主堆和匿名映射。将 glibc 配置作用于单次调用后，同一产物的三次峰值为 412,732、410,992 和 409,828 KiB，耗时 5.55–5.64 秒。

## 构建复测

使用现有 `bench/run.py --build-only`，保留相同的输入、构建次数、验证和产物对比。表中为完整保护原生构建器与 Wasm CLI 的合计最大观测值，每档三个原生进程和一个 CLI 进程。

| 输入大小 | 最大耗时 | 峰值 RSS |
| --- | ---: | ---: |
| 64 KiB | 1.018 s | 482,308 KiB |
| 512 KiB | 1.892 s | 432,804 KiB |
| 4 MiB | 5.604 s | 410,516 KiB |

4 MiB 输入在此配置下达到 A20 的 10 秒和 524,288 KiB 工程门槛。独立产物校验及构建记录重放通过，二进制身份和产物体积记录与 S55 一致。4 MiB 输出 SHA-256 为 `586d15017683bf7432bd8a876ff3548ec00d19eb3eedfe1cb30e32c6794c39cd`。S55 的正式 holdout 报告仍记录 A20 为 `NOT_RUN`。本切片验证 Linux/glibc 的进程级配置。

## 复现

从 S55 的 Linux 源码目录运行。保留 S55 的工具链 PATH、主机记录和 Wasmtime C API 目录，并使用新输出路径。

```bash
env MALLOC_ARENA_MAX=1 MALLOC_TRIM_THRESHOLD_=16384 MALLOC_MMAP_THRESHOLD_=16384 \
  python3 -B bench/run.py --compare-fuel-v2 --a17-holdout-dataset --build-only \
  --frozen-workers _build/tuning-nov26 --out _build/a20-build-only \
  --source-revision 60100c21c77e3e1fe159e21c73d76bddde7e8894 \
  --host-record host-live.json \
  --wasmtime-c-api /root/s26-tools/wasmtime-v50.0.0-x86_64-linux-c-api
```

[构建归档](../../_build/s56-archive/a20-build-only.tar.gz)的 SHA-256 为 `c9a5a128efa142df650d72d0cdf025a1ce85bea64b972ac44c4993f560f32836`。交错复测的单次结果见 [allocator-repeat.log](../../_build/s56-archive/allocator-repeat.log)。
