## 复现

执行环境为 x86_64 Ubuntu 24.04 WSL2，工作区位于 Linux 文件系统。
MoonBit 为 `0.1.20261104 (940aa18)`，wasmoon 为 `0.18.0`，
Wasmtime 为 `50.0.0`，wasm-tools 为 `1.263.0`。完整入口使用 8 MiB
进程栈和 512 KiB Wasmtime Wasm 栈，交付组用 root 和私有 mount namespace
验证真实权限与磁盘满故障。

```bash
python3 -B integration/acceptance/check.py --jobs 12 --out _build/s17/release-evidence
python3 -B integration/acceptance/self_test.py --out _build/s17/self-test-final
python3 -B integration/generated/check.py replay --seed 170026 --index 19
```

独立重放还可直接运行 `cases.jsonl` 写出的单例 worker argv 或其关联的
WAST 指令。机器报告格式、分组与缩减命令见 [验收入口说明](../../integration/acceptance/README.md)。

## 故障对照

| 实际用例 | 结果 |
| --- | --- |
| `success` | 只选拒绝组，得到 `PASS` 和退出 0，整体 `NOT_RUN`。 |
| `injected` | 在真实插桩产物上注入错误的返回值预期。得到 A14 `FAIL` 和退出 1。 |
| `missing` | 通过空 PATH 调用入口。得到 A14 `BLOCKED` 和退出 2，JSON 保留缺失工具详情。 |
| `pending` | 只选性能和发布组。得到 `NOT_RUN` 和退出 2，JSON 仍有 24 项。 |
| `retry-bad` 与 `retry-good` | 用缩减配方重放。原反例与缩减反例均为 Wasmtime 插桩模块的 `run` 返回值断言，保留注入退出 1，恢复真实预期退出 0。 |
| `nested_timeout` | 运行已启动的嵌套子进程后触发外部期限，验证子进程未在期限后写出完成标记。 |

## 独立审查

子代理使用 `/check` 完成只读对抗审查和反例复现。主代理修复并复验。

| 严重程度 | 反例及修复 |
| --- | --- |
| P2 | 同引擎的两个不同断言可能被缩减器当成同一问题。按引擎、原／插桩变体及断言类别和目标保留失败，记录原例、缩减例以及每次试验。 |
| P2 | 内层创建新进程组时，外层超时后孙进程仍能写文件。嵌套工具继承外层进程组并用文件收集原始输出，增加真实清理探针。 |
| P2 | 悬空输入导致源清单读取失败时没有 JSON。将源快照错误写为 `BLOCKED`，检查输入文件类型，并排除当前证据子目录。 |
| P2 | 旧检查的固定产物目录会被下一轮覆盖。统一入口给每个检查分配独立原始证据目录，并保留实际使用的插桩器及 runner 快照。 |

独立复审分别重放了嵌套超时、悬空链接与 FIFO、同一引擎的两种断言失败，以及
两次独立证据运行。复验通过，未发现剩余阻塞项。
