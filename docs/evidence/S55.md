# S55 · 短叶函数内联与 A17 独立验收

## 实现

在 Fuel、Growth、Stack 和局部变量合并之后，展开受限的直接调用。候选叶函数的签名固定为 `i32 -> i32`，没有局部变量，只有一个静态 Fuel guard，且函数体限于短的整数指令和读取指令序列。展开保留已有的 Stack 预留与失败站点，并复制叶函数自己的 Fuel guard。生成后逆向重建源调用，比较重建前后对应模块的编码字节，再对实际展开产物运行 Wasm 验证和 `A ≤ C` 布局核验。超出共享帧成本的候选使用已核验的局部变量合并版本。交付核验先识别并还原生成的内联块，然后扫描源函数的计费块和站点。依据为 [v4 §2 和 §4](../14_FuelGuard生产规格_v4.md)。

旧管线通过 AST 相等性判断是否发生内联。含 NaN 的 runner 输入即使没有发生内联，也因浮点比较结果进入了重建检查。当前管线使用改写器报告的结果，并在实际改写时比较编码字节。使用同一份旧 runner `scalar-source.wasm` 重放时，旧 CLI 退出 2 并报告重建不一致，当前 CLI 退出 0，`wasm-tools validate` 和 `instrument verify` 均通过。带独立 NaN 函数和实际叶函数展开的用例还在两个引擎上检查了正常返回、Fuel 不足及调用深度不足。
