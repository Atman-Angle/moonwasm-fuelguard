# S39 · 分支汇合后的栈检查复用

2026-11-20（北京时间）。本切片在不改变申报书和 FuelGuard v4 门槛的前提下，
减少可证明重复的栈限额比较。

## 实现

当 `if/else` 两个分支都成功检查了同等或更大的直接被调帧成本，且分支内没有
`br`、`br_if` 或 `br_table` 时，汇合后的代码沿用两条路径共同保证的较小上限。
含分支跳转的结构不跨该 `if` 传播证明。`return`、`unreachable` 以及无条件跳转后的
死代码不能增加证明。代码生成器和独立 Stack 审计器按相同保守规则处理。每次调用的
栈预算预留/归还、失败位置、导入和间接调用路径均保留。

影响范围仅为内部 Stack 重写与审计实现，以及对应白盒测试；无公共接口、配置或依赖变化。
