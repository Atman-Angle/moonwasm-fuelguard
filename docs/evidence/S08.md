# S08 增长保护验收

执行日期为 2026-11-16，Git 基线为 `b6a4783`，产物从当前工作区生成。验收范围为 [docs/07 S08](../07_任务分片_MoonWasm_Instrument.md#s08-实现memory与externref-table增长保护) 的 A09 和 A10。

## 实现

CLI 接收 `--max-memory-pages` 和 `--max-table-elements`。插桩阶段检查已配置资源的初始大小。每个实际出现的增长指令要求对应的显式上限。支持定义的非共享 wasm32 memory 和定义的 externref table32。可变 funcref 表指令继续拒绝。

配置增长上限时，内置管线在一个 `FuelGrowthPass` 中生成静态计费和增长保护。生成器按原模块分配 site，最多追加一个 memory helper 和一个 table helper，分别在类型、函数和代码段尾部追加。参数顺序是原始 delta 或 externref、delta，最后追加诊断 site。helper 先读取当前容量并检查 `current <= limit`，再检查 unsigned `delta <= limit-current`。通过后复用 S07 的 checked i64 动态扣费模板，最后执行原始 grow。原模块声明的 maximum 保持生效，原生返回 `-1` 后已付费用保留。完整模块经过验证后才编码。

| 场景 | memory | externref table |
| --- | --- | --- |

含一个函数 import 的样例验证了两处 grow 复用同一 helper、函数引用保持原索引，且 import 声明及顺序一致。组合样例同一模块同时执行两类 grow，返回 `(1, 1)`。两引擎均验证非 null externref 经 table.grow 或 table.fill 后可按原值读回。缺少对应 grow 上限和对 funcref table 执行 grow 的样例以退出 2 拒绝，未产生输出。
