`60100c21c77e3e1fe159e21c73d76bddde7e8894`。候选源码版本仍为工作树

## 影响范围

修复针对 starshine 0.3.0 的 RC 编译兼容性。根模块及 `x@0.5.1` workspace
继续应用 20261126、20261127 补丁；Linux runner 的 `x@0.5.5` 返回
`ArrayView[String]`，使用 20261126、20261128 补丁并转换为 `Array[String]`。
影响依赖准备脚本、`cmd/run` 的本地文件遍历和相关第三方补丁说明。没有更改
FuelGuard 公共接口、调用方、manifest 或外部依赖版本。

## 未验证与解除条件

- Linux `moon test --frozen --target native`、Linux 样例及 `scripts/check-e2e.sh` 未验证。当前 WSL `FuelGuard-S26` 没有 `moon`、Wasmtime 或 wasm-tools；本轮固定 MoonBit 下载仍有 S60 记录的 HTTP 403。需在已有工具齐备且使用 ext4 的 Linux 环境重跑。
- wasmoon/Wasmtime 双引擎验收、完整语料和拒绝路径、A17/A19/A20 最终候选性能哈希复核及干净安装均未验证。当前 ZIP 成员及许可通知文件通过本地检查，但其中传递依赖另由 package manager 获取，尚无干净安装运行证据。S59 及更早性能记录为历史证据，不作为本轮结果。
- GitHub Actions workflow 尚无本候选运行记录。需外部 CI 可访问所固定的 MoonBit 发布资产后触发并检查真实 job 结论。
- 原有工作树源码改动均保留。两个 starshine 生成缓存在重建前被整体移动到 `starshine.audit-backup-arrayview-fix` 和 `starshine.audit-backup-root-arrayview-mismatch`，没有删除。试验期间意外解压到仓库根的临时 `$tmp` 目录已核实为本轮生成内容并移除。

结论：本轮确认修复了 `cmd/run` 对 `x@0.5.5` 的编译兼容问题，并通过根模块与 runner 类型检查；这不满足正式验收条件，待 Linux 运行时、双引擎、性能、发布包及独立复审补齐。
