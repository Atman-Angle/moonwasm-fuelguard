# S50 · A17 性能优化复测

2026-11-26（北京时间）。本切片继续处理 S49 的 A17 `FAIL`。唯一实现与验收规范为 [FuelGuard 生产规格 v4](../14_FuelGuard生产规格_v4.md)。门槛维持 Wasmtime 与 Wasmoon hot/lifecycle 应用几何均值比的 95% CI 上界均不超过 `2×`，不调整验收函数、Fuel 语义、Stack/Growth 保护或 ABI。

## 变更及依赖

Fuel 生成器仅在直接调用的目标可能改写 Fuel 时重新读取缓存，并计算可能改写 Fuel 的函数传递闭包。缓存启用条件按静态 span 数和动态费用特征筛选。动态 surcharge 可在函数缓存中完成余额检查与扣费，并在原始可能 trap 的 memory/table 操作之前发布余额。Stack v2 失败分支使用空成功分支和失败 `else`，减少生成的条件指令。

这些改动影响 `plan_fuel`、`rewrite_expr`、动态费用模板、Fuel span proof，以及 Fuel/Stack v2 验证和对应测试。调用者是内建 Fuel v2 `instrument -> Fuel -> Growth -> Stack` 管线。没有发现新增或删除 import、数值索引、计费公式、失败诊断、Stack/Growth 保护、外部 runtime 依赖或 ABI 变化。`fuel_span_proof` 允许符合规则的多 span 无缓存输出。
