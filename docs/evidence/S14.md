# S14 生产 CLI、manifest 与原始指令位置验收

执行日期为 2026-11-17。Git 基线为 `b6a4783`，测试包含工作区中已有的 S01–S13 实现。验收依据为 [任务计划](../07_任务分片_MoonWasm_Instrument.md) 的 S14 及 [验证计划](../09_验证与验收计划.md) 的 A16、A23。静态 JSON 契约见 [manifest v1](../implementation/manifest-v1.md)。

## 结果

| 验收 | 实测结果 |
| --- | --- |
| A16 确定性 | 在三个新输出路径以相同输入和配置运行 `cmd/instrument`，产物 Wasm 与完整 JSON 逐字节一致。重排和重复导入许可仍生成相同 JSON。省略 `--report` 时 Wasm 字节一致。Python 独立计算并核对输入及输出 SHA-256，`wasm-tools validate` 校验编码后的实际产物。JSON 缺省限额为 `null`，i64 极值按字符串无损保存。 |
| A16 版本追溯 | 在隔离源码副本中仅将 `cost_model.mbt` 的 `fuel_v1_version` 由 `fuel-v1` 改为 `fuel-v2`，使用同输入和配置构建并显式选择 `--cost-model fuel-v2`。产物的版本标记和 Wasm SHA-256 变化，manifest 中只有 `fuel_model` 和 `output_sha256` 变化。此试验只变更标识，费用规则与主工作区版本保持原状。当前 CLI 和 runner 均拒绝试验版本，退出 2。 |
| A16 原始位置 | Wasmtime 50.0.0 与 wasmoon 0.18.0 都读取实际 trap globals，分别得到 Fuel `(1,7)`、Memory `(2,9)`、Stack `(4,5)`、直接调用 Depth `(5,11)`。独立按源 WAT 计算的坐标是函数 2 的 `if` 序号 1、`memory.grow` 序号 3、函数 2 的外部入口、函数 2 的 `call` 序号 5，与 JSON 一致。独立 fixture 还验证间接调用 Depth `(5,6)` 映射到函数 2 的 `call_indirect` 序号 1，Table `(3,4)` 映射到函数 0 的 `table.grow` 序号 2。导入函数的导出入口和 core start 入口均在映射内。 |
| A16 配置和摘要 | 拒绝未知 profile/模型/选项、重复模型/报告参数、非法报告值、报告与输出同名、歧义导入、缺失资源上限和裸负号。接受严格配对的导入 `--env.fn` 及数值 `0`。CLI 摘要及 JSON 中 production-v1 列出 Fuel → Growth → Stack，两个兼容 profile 列出 Fuel → Growth。通过独立二进制节计数校验追加的函数、类型、全局索引范围。特性用例验证 v128 值类型、多值签名、固定 funcref 和 externref 表均被记录。 |
| A23 迁移 | 从 `b6a4783` 在隔离目录实际构建旧 CLI 并生成旧原型产物，现有 CLI 因保留导出冲突拒绝重新插桩，runner 因缺失生产标记拒绝加载，两者退出 2。CLI 拒绝重复插桩并拒绝未知模型。兼容 profile 产物标记与 `production-v1` 区分。 |

## 复现

Windows PowerShell 7，MoonBit `0.1.20261016 (1af328f)`。

```powershell
moon info --target wasm --target-dir _build/s14-pwsh
moon fmt --target-dir _build/s14-pwsh
moon fmt --check --target-dir _build/s14-pwsh
moon check --target wasm --deny-warn --target-dir _build/s14-pwsh
moon test --target wasm --target-dir _build/s14-pwsh
python -m unittest discover -s integration/fuel_oracle -v
git diff --check
```

Linux Ubuntu 24.04 WSL2，MoonBit `0.1.20261104 (940aa18)`，wasm-tools `1.263.0`，双引擎版本如上。运行前将锁定工具加入 `PATH`。

```bash
PYTHONDONTWRITEBYTECODE=1 python3 integration/manifest/check.py
bash scripts/check-cli-failures.sh
PYTHONDONTWRITEBYTECODE=1 python3 integration/runner/check.py
```

Windows Wasm 单测 85/85，独立 Fuel 预言机 9/9。Linux S14 用例包括 27 次 CLI 调用，其中 13 次正常退出 0，14 次按预期拒绝并退出 2。独立校验了 19 个输入及产物，6 个 trap 场景均通过两个引擎。既有 CLI 失败路径脚本及 S13 runner 回归通过。

独立子代理使用 `check` 审查本次变更。根据复现修复了连字符导入名与报告值的解析、裸负号资源上限及源特性清单三处问题，并为这些反馈补了 CLI 回归用例。审查者在 WSL 原生临时目录复制当前源码与验收脚本并重新构建，独立复跑 27 次 CLI 调用和 12 次引擎用例，全部通过。复核没有遗留 S14 必修项。

版本探针在独立目录复制根模块的 `.mbt`、`moon.mod`、`moon.pkg` 与 `cmd/instrument`，更改上述版本标识后重放日志中的 `cli-same-0` 配置，唯一改动的选项值是 `--cost-model fuel-v2`。比较两份 JSON，并由当前 Linux runner 加载试验 Wasm 核对退出码。旧原型用 `git archive b6a4783` 解到另一个独立目录，以 `moon run cmd/instrument --target wasm -- minimal.wasm -o old-metered.wasm --fuel 100` 生成，`minimal.wasm` 由同一集成脚本生成。
