## 交付与迁移

- `cmd/instrument` 和公共生产管线默认使用 `fuel-v2-inline-v1`，旧布局无法用于生产生成。CLI 旧布局和旧模型选择退出 2，并提示用未插桩的原件重建。
- CLI 升为 0.2.0。新 [manifest v2](../implementation/manifest-v2.md) 记录模型与布局版本、配置、输入和输出哈希及确定性声明。历史 v1 配对仍按各自的 Wasm marker 验证。显式兼容 profile 沿用其计费模型。
- 验证器读取 Wasm guard 的首站点和费用，使用相邻首站点与函数末站点恢复长度，再核对规划时生成的摘要。版本化 Wasm 自定义节记录 32 字节摘要和每个原定义函数 4 字节的末站点，完整体积已计入下表 Wasm 大小。

## 复现

在 Linux 文件系统中的项目根目录执行。使用新输出目录和 S29 的两份冻结实物，
归档路径见 [S32](S32.md)。

```bash
python3 -B integration/manifest/check.py
python3 -B integration/fuel_v2/check.py --out _build/s34-f0
python3 -B integration/fuel_v2/workloads.py --out _build/s34-workloads \
  --compact-v1 /path/to/s29/initial --compact-v2 /path/to/v2-benchmark
```

独立 `/check` 审查发现两项 P2（生产库仍可生成旧布局、缓存 guard 未绑定余额 local）
和一项 P3（零末站点未核对函数体）。三项均已修复并通过独立复核。
完整正确性体系迁移、正式性能与体积门禁由后续切片验证。
