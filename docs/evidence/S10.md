## 独立手算与执行

[验证脚本](../../integration/policy/check.py) 从 WAT 装配样例，调用实际 CLI 后核对完整布局。样例含 v128 local 和 v128 运算、多结果 block、br_table、不可达多态栈，以及实际生成的 memory Growth helper。样例声明结果和量均可手算：

| 函数 | 最终参数 / 结果 / local / 操作数 / 帧 | 同时活跃辅助帧 | A | C |
| --- | --- | ---: | ---: | ---: |
| typed，索引 0 | 1 / 2 / 5 / 6 / 8 | 0 | 22 | 145 |
| grow，索引 1 | 1 / 1 / 1 / 3 / 8 | 17 | 31 | 137 |
| Growth helper，索引 2 | 2 / 1 / 3 / 3 / 8 | 0 | 17 | 64 |

typed 的两个 v128 local 占 4 单位，Fuel 再追加 1 单位。原程序 v128.and 前峰值 4，最终布局的内联比较再占 2。grow 调用时调用者的 14 单位与 helper 的 17 单位相加。原程序的最大签名压力 S=3，C 按共同模板上界计算。独立 wasm-tools 通过，原始和插桩字节在 wasmoon 和 Wasmtime 均返回 `(7, 9)`。

白盒检查覆盖：
- v128 宽度、不可达多态路径和可达峰值。
- 连续 helper 调用取最大，嵌套帧相加，生成入口保留其帧且不递归计原调用图。
- A=C 可接受、A=C+1 拒绝，生成 helper 递归环拒绝。

F2 `lisp_eval` 的真实大帧与最小 SIMD 也经过插桩前后栈审计。CLI 输出 351 行布局，最终 local 成本最大为 524 单位。按锁定工作负载的预期输出对照，F0、F2、F3 各自的插桩字节在两套引擎验证了正常输出。F1 的范围冲突见 [S09](S09.md)。
