# S02 证据：Linux 双运行时验证驱动

执行日期：2026-11-10。验收条件见 [07 S02](../07_任务分片_MoonWasm_Instrument.md#s02-建立linux双运行时验证驱动)。

## 验证范围

- 固定 S01 的 F0–F3 原始二进制 SHA-256。两引擎分别执行相同的 Wasm，核对 WASI stdout。
- 用仓库自身的 MoonBit CLI 生成粗粒度 Fuel 原型 F0（`--fuel 100000`），独立校验编码后的字节，比较 F0 的 import 声明并核对 stdout。
- 三个 WAT 用例覆盖 i32 返回值、读取诊断 global 的 guest getter、普通 `unreachable` 和 core start `unreachable`。两个 CLI 都按用例启动新进程。失败时记录退出码和原始日志。CLI 模式的 trap 实例不可供宿主读取，start 失败记录为初始化诊断不可用。
- 每次运行记录工具二进制与产物 SHA-256、原生栈配置、标准输出与标准错误的哈希及退出码。超时是验证失败。

Linux 进程 `RLIMIT_STACK` 软限为 8 MiB、硬限无限。wasmoon 使用默认 JIT 路径，
其 0.18.0 CLI 源码为 JIT native fiber 配置 16 MiB，core start 在实例化阶段执行。
Wasmtime 显式设 `max-wasm-stack=524288`，fuel 和 epoch 保持默认关闭。
运行时子进程限时 30 秒，本次无超时。当前 WSL 可见 22 个逻辑 CPU
（Core Ultra 9 185H）和约 15.3 GiB 内存，性能认证环境由 S18 冻结。
