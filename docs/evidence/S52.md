# S52 · F2 Wasmtime Guest Profile 诊断

2026-11-26。该切片建立可采到样本的 Wasmtime guest-profile 方法，作为 [S51](S51.md) 零样本 profile 试验的后续诊断。FuelGuard v4 的 A17 门槛与 Fuel、Growth、Stack 语义均未改变。本切片不构成 A17 性能验收。

## 方法

F2 原始应用的 `_start` 运行时间短于默认 100 ms 采样周期。诊断脚本通过 `wasm-tools print` 将冻结 F2 模块转成 WAT，只修改数据段里的 `(fib 18)` 为 `(fib 30)`，再用 `wasm-tools parse` 生成诊断模块。指令段、函数索引和控制流保持原样。缓存的 Fuel v2 build worker 分别生成 Fuel-only 和完整保护模块。每个变体均由 Wasmtime 50 guest profiler 以 1 ms 间隔执行 3 次，所有模块先通过 wasm-tools 验证，且 stdout 必须逐字节一致。

诊断入口为 [profile_guest.py](../../bench/profile_guest.py)。它将缩放后的输入、三个 Wasm 模块、每轮 profile、输入/工具/worker 摘要和样本函数分布写入指定的新目录。

在 Windows PowerShell 进入仓库后执行：

```powershell
wsl -d FuelGuard-S26 --exec bash -lc 'cd /mnt/d/moonwasm-fuelguard && python3 -B bench/profile_guest.py --source /root/fuelguard-s49-run/_build/a17-dynamic-cache-active-tuning/F2-lisp/original.wasm --wasm-tools /root/s26-tools/wasm-tools-1.263.0-x86_64-linux/wasm-tools --wasmtime /root/s26-tools/wasmtime-v50.0.0-x86_64-linux/wasmtime --build-worker /root/fuelguard-s49-run/_build/a17-dynamic-cache-active-tuning/build --out /mnt/d/moonwasm-fuelguard/_build/a17-profile-replay --fib 30 --runs 3'
```

该命令要求输出目录尚不存在。临时诊断样本不进入 `bench/dataset.json`。
