# S54 · Fuel v2 热路径与叶函数内联诊断

2026-11-26。该切片在 `_build` 隔离副本中比较 Fuel guard 形状、余额传播、扣后值转发和短叶函数内联。唯一实现与验收依据仍为 [FuelGuard v4](../14_FuelGuard生产规格_v4.md)。本页样本不是正式 A17 结果。

## 环境

使用 Windows MoonBit `0.1.20261119 (738607b)`、冻结 WSL `FuelGuard-S26` 中的 Wasmtime 50.0.0 和 Wasmoon 0.18.0，以及 wasm-tools 1.263.0。隔离副本把 starshine 0.3.0 的 `Show`/`Hash` 旧式方法调用改为显式 trait 调用，仅为兼容当前编译器。F1/F2/F3 模块均由当前副本 CLI 从冻结 tuning 原件生成，并通过内建 verify 与 wasm-tools validate。

每个引擎/应用/窗口使用同一 schedule，包含 95 个随机交错周期及 5 个预热周期，汇总后 90 个观测中位数。本诊断未作进程级 bootstrap，不作验收判定。

## 热路径实验

### 失败分支形状

把 Fuel guard 从“非负余额进入空分支”改成“负余额直接进入 trap 分支”后，MoonBit 123 项测试通过，CLI 构建成功，F1–F3 六个变体均通过 CLI verify。候选输出只有至多 4 B 变化。相对原件的 Wasmtime 比值如下。

| 应用 | Hot 几何比 | Lifecycle 几何比 |
| --- | ---: | ---: |
| F1-json | 2.237× | 2.195× |
| F2-lisp | 2.611× | 2.613× |
| F3-sha256 | 1.698× | 1.734× |

候选相对当前基线在 F2 hot 约慢 0.5%，lifecycle 约快 0.9%，没有一致收益，方向停止。

### Cache 同步数据流

隔离 `rewrite_expr` 试验把可证明已同步的余额状态传入结构化子表达式。MoonBit 123 项测试通过，CLI 构建及三个代表产物 verify 通过。相对基线的 Wasmtime 候选/基线比为 F1 hot/lifecycle `0.949× / 0.958×`，F2 `1.026× / 0.985×`，F3 `0.987× / 0.984×`。产物分别只少 4、16、4 B，单轮测量变化较小且方向不一致。

F2 放大 profile 输入 `(fib 30)` 的隔离结果为 5,515 个 guard 静态位置累计执行 28,458,790 次、Fuel global get 17,054,838 次、Fuel global set 15,028,652 次。原 fixture 的 F2 Wasmtime tuning 中位数相对比远高于放大诊断的精度范围。计数只说明这个诊断输入中操作执行频度，不直接代表 CPU 周期。

### 函数尾部重载

若一个缓存函数的最后一条原始指令是会改写 Fuel 的调用，且之后无计费点，则省略局部余额重载和退出前发布。MoonBit 123 项测试、CLI build、交付 verify 与独立 wasm-tools validate 均通过。候选相对基线 Wasmtime 比值为 F1 `1.003× / 1.010×`，F2 `0.983× / 0.991×`，F3 `1.008× / 0.998×`。F2 hot 有小幅收益但跨应用不一致，不采用为生产改动。

### 扣后值局部转发

无局部缓存路径把扣后的全局余额写回时，用临时局部保留同一值以替代紧邻的 global.get。MoonBit 123 项测试、CLI build、交付 verify 与 wasm-tools validate 均通过。候选相对基线比值为 F1 `0.990× / 1.003×`，F2 `1.005× / 1.005×`，F3 `0.991× / 0.992×`，且产物增长 46–66 B。此路线没有收益。

## 短叶函数内联

先前记录的宽松 WAT 内联筛选没有可靠排除带局部变量的缓存函数，并曾展开非叶 evaluator。该筛选未满足“短叶函数”的前提，因此这里撤销其 Wasmtime/Wasmoon 几何比、lifecycle 比和体积变化作为性能证据。原始记录只保留为已证伪实验的审计线索，不能据此预测正确筛选后的收益。

后续诊断必须显式要求单个静态 guard、无局部变量、无调用、无 block/if/loop，且签名为 `i32 -> i32`。在确认这些结构条件前，任何 WAT 计时都不纳入路线判断。

MoonBit 后置内联原型在 Stack/Fuel 审计之后、local coalescing 之前展开同类调用。隔离副本 123 项测试通过，F1/F2/F3 的 Wasmtime hot 相对基线为 `0.806× / 0.903× / 0.816×`，lifecycle 为 `0.797× / 0.900× / 0.810×`。当前 `verify_fuel_v2_spans` 会扫描内联后的调用者并拒绝重复或非单调的源 span 站点，所以产物未通过交付验证。正式候选未生成。

前置内联原型尝试在所有保护规划前直接改写源模块。普通单元测试仍通过，但交付 span 证明无法重建重复叶函数站点，说明全局 Fuel site 分配必须认识代码克隆；该实现已停止。

后置内联还有未完成的 Stack 合约验证。最终帧布局必须以实际内联产物重新计算，并证明共享 `C` 足以覆盖内联后的 caller operand peak；正式 verifier 必须能把已证明的 inline block 还原成原始 source call，随后审计 Fuel span、Stack call reservation、A≤C、最终 Wasm，并在 Wasmtime 和 Wasmoon 上重跑受控 Fuel 失败、返回值和输出前缀用例。性能候选不能替代这些条件。

## 决定与状态

失败分支形状、局部同步保守传播、尾部重载省略和扣后值局部转发均未得到跨代表应用稳定收益，不进入生产实现。短叶函数内联是当前值得继续的架构候选，但目前不满足交付与 Stack 审计条件，不能进入正式调优候选冻结。

当前正式 A17 仍为 `FAIL`。旧 holdout 不能测试新实现，必须先完成 inline proof 与 A≤C/Stack 审计，再运行 v4 正式 tuning、冻结候选、独立 20 进程 holdout 和 correctness gates。生产源码没有变更。
