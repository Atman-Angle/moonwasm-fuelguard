# S09 输入策略验收

执行日期为 2026-11-16，Git 基线为 `b6a4783`，使用当前工作区。范围为 docs/07 S09 的 A11、A15 和 A23。

## 策略与保障

- CLI 默认使用 `production-v1`。非共享 wasm32 memory、内部固定 funcref table、externref table 等按生产允许表校验。存在的 memory/table 必须显式设置相应上限。
- `preflight_production_wasm` 在 Starshine 解码之前检查字节数、段计数、名称 UTF-8 与长度、签名、local、指令数和结构深度。扫描器按指令立即数推进，在段和函数体边界处检查截断。它读取长度、计数和必要标记，结构层数用迭代计数。合法结构再交给解码、AST 策略和完整 Wasm 验证。4 MiB 是 decoder 输入上限。现有文件适配器仍将文件一次读入内存，尚无流式有界文件读取。
- 函数与 i32/i64 global import 必须精确匹配 `(module, name)`。CLI 采用一个点号分隔两个非空名字，歧义和含点的名字无法通过这个 CLI 地址语法。Memory/table import 和 table export 始终拒绝，允许列表无法覆盖禁用种类。
- 源操作必须有冻结费用规则。relaxed SIMD、未列入的 SIMD、可变或逃逸 funcref、禁用的类型和指令有明确错误。普通未知 custom section 保留。Starshine 会进一步解释结构化 `compiler.facts` 内容，因此生产预检显式拒绝该依赖专有段，避免对其嵌套元数据调用无界解析。
- `--profile legacy` 显式选择兼容路径，输出 note 和 custom marker 都标注 legacy。新版 marker 标注规则表、诊断 ABI 和当前逐指令计费布局。旧诊断保留名、重复 marker、未知 marker、未知 `--cost-model` 和未知 profile 均拒绝。旧插桩产物不会被当作新源码重新插桩。

## 验证

[x86_64 Linux 验收入口](../../integration/policy/check.py) 从工作区构建 MoonBit CLI。它检查预期拒绝退出 2 且不创建输出，独立校验所有接受产物，经打印比较 import 种类、顺序和索引。用例覆盖：

| 条款 | 实际检查 |
| --- | --- |
| A11 | 函数/global 正向放行与未声明拒绝，memory/table/tag 即使列在允许表仍拒绝，含点 module 无法与另一二元组碰撞。 |
| A15 | 深度 256 和 locals 4096 接受，257 层和 4097 locals 在解码前拒绝。额外检查模块字节、导入/类型/函数/global/export/段计数、参数和结果、单体及总指令数、元素数量、截断体、LEB 溢出、UTF-8、非法 block type、SIMD 和 funcref。 |
| A23 | 旧保留诊断名、重复 marker 和未知 marker、未知规则表/profile 拒绝。显式 legacy 产物标注兼容路径并通过独立校验。 |

F0、F2、F3 使用原始锁定产物和显式 WASI allowance，并通过预检、插桩、独立验证和双运行时预期输出比较。F1 `json_parse` 实际含三个 mutable f64 global，与 S01 允许表的 i32/i64 global 条目冲突，因此 production-v1 明确拒绝。该冲突留待范围决策，原始样例和支持矩阵未被放宽。

```bash
export LC_ALL=C
ulimit -S -s 8192
mkdir -p _build/s09-s10
set -o pipefail
python3 integration/policy/check.py 2>&1 | tee _build/s09-s10/run.log
bash scripts/check-cli-failures.sh

```

环境沿用 S02 锁定的 wasmoon 0.18.0、Wasmtime 50.0.0 和 wasm-tools 1.263.0，Linux MoonBit 0.1.20261104 (940aa18)。产物与每条命令的退出码、stdout 和 stderr 哈希见 `_build/s09-s10/run.log`。验收脚本记录 50 个预期拒绝及 8 个独立校验通过的产物。S02 双引擎回归和 CLI 错误路径回归也均退出 0。支持矩阵上限仍为暂定值，最终压力冻结由 S20 完成。
