## 冻结环境和比较组

使用 S26 的 `FuelGuard-S26` Linux x86_64 环境。守卫核对 S26 原始环境记录的
SHA-256、Linux CPU、内核及发行版、Windows 主机、电源方案、vCPU 4 亲和性、
8 MiB Linux 栈上限、单调时钟、Python 和工具摘要。Mooncakes 依赖、
wasmoon 0.18.0 的 JIT 配置和 Wasmtime 50.0.0 的 C API 配置沿用 S26。S29 的两个计时 worker
增加同进程九模块容量，实际二进制、编译命令和 Wasmtime C API 库随原始账本归档。

使用 S25 冻结调优语料，清单 SHA-256 为
`ada027679aaab88d850b33e7129b5b5b9fbbcff2b2bc2e8316560b547aca8836`。
每个进程交错执行原版、Fuel-only P0、P0/P1/P2、`p2-prefix`、
`join-span`、`join-span-cached` 和 `join-span-compact`。两引擎对
F0–F3 和调用微基准测生命周期及热调用，对 start-only 微基准测生命周期。
生命周期计入实例化及 core start。每个适用单元各跑 3 个独立进程，每进程
每变体 5 次预热、300 次计时。worker 逐样核对业务结果。保留集执行数为 0。

## A17 正式计时

首轮的 66 个独立进程保留 178,200 条正式样本、2,970 条预热样本和
594 条引擎编译记录。统计按引擎和窗口分开，使用种子 `180027`
进行 10,000 次分层配对 bootstrap。先采进程组，再采该组内完整交错周期，
分位数使用线性插值。F0–F3 的中位数比几何平均取 95% 区间上界与 2×
比较，各个代表负载的中位数比和 p95 比上界与 3× 比较。微基准单列。

首轮七个布局均有至少一项几何平均 95% 下界超过 2×。首轮有 11 个
单元的逐项区间跨线，因此为这些单元再追加 3 个进程，按与首轮相同的
预算、时间窗口、worker 和 Wasm 字节交错运行九个变体。补采排程继续使用
冻结种子及新的进程组编号。

补采保留 89,100 条正式样本、1,485 条预热样本和 297 条引擎编译记录。

| P2 | A18 可凭无关的成功日志通过 | 重放逐项核对原始日志摘要、两引擎与全部布局的临界用例 |
| P2 | A18 可缺少 debug 插桩器和见证产物 | 归档并核对插桩器和产物，验证缺失账本记录会失败 |

native wasmoon worker 构建及检查均通过。S26 的 30 × 3 历史报告成功重放，
