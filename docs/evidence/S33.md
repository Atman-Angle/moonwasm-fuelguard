# S33 · 31 位唯一栈配置域

2026-11-20（北京时间），分支 `feat/v4-fuel-v2`，基线提交 `60100c2`，工作树承接 S30–S32。
[工单 004](../../.scratch/fuelguard-v4/tickets/004-31位栈配置域.md) 状态为 PASS，无阻塞。
实现依据是 [生产规格 v4 §2.2](../14_FuelGuard生产规格_v4.md#22-stack-height-limiter) 和 [ADR-0003](../adr/0003-31bit-only-stack-config.md)。

## 变更

- `StackConfig::new` 与 CLI 参数解析接受的栈单位和深度都是 `1..=2147483647`。Stack 计划检查原函数的 C，最终审计同时检查所有行的 C 和 A ≤ C。
- 所有有 StackPass 的产物只生成打包预留和归还。两项初始声明供 runner 在实例化前检查，首次入口将二者打包，原深度全局作为初始化标记。删除双计数器预留、归还及回退测试。
- 新 marker 和 manifest 记录 [stack-v2](../implementation/stack-v2.md)。旧 `stack-v1` 配对仍可验证，并可在既有 Linux runner 限额内运行。生成接口的本票变化为 `verify_builtin_artifact` 新增可选 `stack_model` 参数，用于精确核对报告版本。

## 复现

在 Linux 文件系统中的工作树根目录执行，输出路径使用新目录。

```bash
FUELGUARD_CHECK_EVIDENCE="$PWD/_build/s33/p0" python3 -B integration/stack_pass/check.py
FUELGUARD_CHECK_EVIDENCE="$PWD/_build/s33/fuel-v2" python3 -B - <<'PY'
from integration.stack_pass import check as stack
stack.runtime.OUT = stack.OUT
stack.OUT.mkdir(parents=True)
stack.CODEGEN = "fuel-v2"
stack.build_instrument("build-cli")
stack.workloads()
PY
FUELGUARD_CHECK_EVIDENCE="$PWD/_build/s33/manifest" python3 -B integration/manifest/check.py
FUELGUARD_CHECK_EVIDENCE="$PWD/_build/s33/pipeline" python3 -B integration/pipeline/check.py
python3 -B integration/fuel_v2/check.py --out _build/s33/f0
python3 -B integration/generated/check.py run --limit 32 --codegen join-span --out _build/s33/generated
```

旧档案的回放校验以冻结的 S29 initial 运行目录及其 `dataset.json` 调用
`bench/summarize.py` 的 `validate_construction(..., variants=S29_VARIANTS)`。
原档案复验 81 条体积和 279 条构建记录。隔离副本中对 56 份清单改标为
`stack-v2`，保持 Wasm 不变，回放拒绝第一份不匹配的 marker。
