# S27 · FuelGuard M2 正确性证据

执行日期为 2026-11-19（北京时间）。分支为 `feat/s27-fuel-oracle`，Git
基线为 `c2a7d16`，从包含 M1 的现有工作树开始。开发前快照保存在
`_build/s27-m1-source`。验证候选是 `join-span-cached`，差分对照是
`join-span`。[原试点](S26.md) 与 [缓存试点](Fuel-optimization.md) 保留
进入 S27 的性能依据。S27 的结果只覆盖正确性验收。

## 实现与独立审查

`integration/fuel_oracle/join.py` 依据版本化契约从结构化源指令建立
带词法标签标识的 CFG。实际执行路径由用例提供。预言机独立计算静态
预扣、可支付前缀、首个不可支付站点、剩余余额、调用和动态费用，
再与真实 Wasm 的 span 清单及双引擎执行比对。旧 v1 预言机继续用于
迁移测试，S20 原始模型指纹保留，S25 后的标量模型及 v1.2 分别有指纹。

独立子代理按 `/check` 做只读对抗性审查和反例复审。主代理处理了以下发现。

| 级别 | 反例 | 修复与验证 |
| --- | --- | --- |
| P1 | 已终止的 then 后仍有不可达的内块分支。预算 5 时，误切允许 else 的 `global.set` 先执行，再在 site 10 陷阱 | 共享规划器分别记录词法标签引用与相对可达出口。新用例以两引擎、两布局各重复 20 次，验证 site 10、精确余额及 `trace=0` |
| P2 | 预言机把不可达尾部、死 `br_if` 的顺序边或另一词法标签错误解释成实际汇合 | 保留 CFG 标签所属结构，独立判断 then 路径能否落穿。覆盖活跃和全死的源指令范围，并核对其 span 表 |
| P2 | 同时清空 `sites` 和 `fuel_spans`，或提供内部自洽的错误拆分 | `instrument verify` 从实际 Wasm 的 replay guards 还原 span 首站点、长度和指令所属函数索引。正常产物和真实空清单通过，双空、错切、错函数及错模型／布局被拒绝 |
| P2 | 统一验收仍默认跑 P0，旧 `demo` 的 Stack 行漏计共享 replay helper | 增加 v1.2 布局选择，接入精确双引擎预言机、具名差分、demo、原生 runner 与 A14。旧 P0 入口及回放保留 |
| P2 | 负载哈希校验只依赖当次数据集 JSON，可能同时替换清单和负载 | 共享 benchmark 清单的冻结摘要，把清单和常量文件纳入统一报告的输入摘要 |

生产共享规划器改动针对不可达分支误判。两个 v1.2 布局继续共用
边界规则。两个布局在冻结 F0–F3 上的 Wasm 和 manifest 与 M1 归档
逐字节一致。独立复审另用 1,000 个合法混合控制结构函数核对完整
span 表，两布局各自与预言机零差异。

## 命令与工具环境

Linux 运行在 `FuelGuard-S26` WSL2 的本地文件系统，仓库镜像为
`/root/fuelguard-s27`。工具版本为 MoonBit `0.1.20261104 (940aa18)`、
Wasmtime `50.0.0`、wasmoon `0.18.0`、wasm-tools `1.263.0`。
Windows 的 MoonBit 版本为 `0.1.20261016 (1af328f)`。

```bash
export MOON_HOME=/root/s26-frozen-moon
export PATH="$MOON_HOME/bin:/opt/fuelguard-s26/bin:/root/fuelguard-s26-optimization/_build/wasmoon-0.18.0-test-source/bin:/usr/bin:/bin"
export LC_ALL=C
python3 -B integration/acceptance/check.py --group correctness --group generated --group rejections \
  --jobs 6 --codegen join-span-cached --out _build/s27/final-cached
python3 -B integration/acceptance/check.py --group correctness --group generated --group rejections \
  --jobs 6 --codegen join-span --out _build/s27/final-frozen
python3 -B integration/acceptance/self_test.py --out _build/s27/acceptance-self
python3 -B integration/p1/check.py --out _build/s27/p1-final
```

Windows 执行了 `moon info`、`moon fmt`、`moon check --target wasm --deny-warn`、
`moon test --target wasm` 和 `git diff --check`。审查生成接口后，S27 相对
M1 快照没有新的 `.mbti` 改动。根包相对 Git 的接口差异来自 M1 增加的
布局枚举、模型版本和布局常量。

## 最终结果与归档

两份最终报告的 13 项检查均通过，返回码为 0，A01–A16 和 A23
在所选组中通过。Windows 和 Linux 的 105 项 Wasm 单测以及严格编译
均通过。独立 Fuel 预言机单元测试为 18/18，P0/P1/P2/P2-prefix 迁移
检查及统一入口的负面自检也通过。

对两份 A14 逐例账本按 case ID 核对同一输入、预期观测和已验证陷阱，
10,000 条完全匹配。各布局的受控陷阱分类为 Fuel 1,667、Memory 833、
Table 833。两个最终报告都记录同一 128 文件源码集合，其摘要为
`b4a026c969e53f60b4a0c32224655ec0e3a7b05aa14d7d5bf19118e1019e61ce`，
