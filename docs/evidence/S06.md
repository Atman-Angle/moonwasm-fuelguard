# S06 证据：P0 静态块内联计费与 i64 预算

日期：2026-11-11。验收条件见 [07 S06](../07_任务分片_MoonWasm_Instrument.md#s06-实现p0静态块计费与i64迁移)。

## 交付

- `FuelConfig` 和 CLI `--fuel` 已迁移到 `1..=i64::MAX`，CLI 对 i64 十进制溢出和负数返回明确错误。
- FuelPass 现在按 S05 的确定性 site 顺序在静态指令前内联 P0 模板。模板先读取 i64 余额并比较，再写入 code/site 诊断并 `unreachable`，成功路径只写回一次 fuel global。
- 每个定义函数追加一个 i64 临时 local，原有参数、local 和 import 索引保持不变。
- `__moonwasm_trap_code` 与 `__moonwasm_trap_site` 作为独立 mutable i32 globals 导出。动态费用 opcode 在 S06 明确拒绝，交给 S07。
- 版本和模式记录在 pass note 中，例如 `version=fuel-v1 mode=P0-i64`。
