## 复现

使用 x86_64 Ubuntu 24.04 WSL2 的 Linux 原生文件系统。MoonBit 为
`0.1.20261104 (940aa18)`，wasmoon 为 `0.18.0`，Wasmtime 为 `50.0.0`，
wasm-tools 为 `1.263.0`。使用 8 MiB 进程软栈限额和 Wasmtime 512 KiB Wasm 栈配置。
工具的固定版本与安装方式见 [运行时设置](../../integration/runtime/README.md)。

```bash

python3 -B integration/pipeline/check.py > _build/s16/pipeline.log 2>&1
```

## 可观察行为与差异

- WASI 按引擎比较原始 stdout 字节，使用 [S01](S01.md) 的输入与预期文本。F2
  在测试用的大预算下输出 `Number(2584)\nNumber(0)\n`。在 Linux 产品 runner
  的深度 128 配置下，三个执行入口均保留 `Number(2584)\n`，产品 runner
  报 code 5/site 594。Wasmtime 的 core dump 读取同一对 code/site。两个通用
  CLI 的终端错误类别均为 `unreachable`。
- F1–F3 的锁定产物分别带有 MoonBit 字符串／数组 SIMD。每份产物的测试副本在原
  `v128.load` 执行后置位，启动导出返回前检查该位。原/插桩探针在两引擎中均通过，
  删除置位的负对照在相同业务输出后触发 `unreachable`。
- 算术 NaN 用 WAST 验证类别，严格子集仅对直接 reinterpret 的字面量检查 payload 与符号。原生整数、
  间接调用和 bulk trap 按陷阱类别验证，插桩产物的诊断全局为 code/site 0/0。
- 实例化时数据段越界按失败阶段判定。Wasmtime 在 1 GiB 地址空间限额下对原/插桩
  模块的内存预留均返回 ENOMEM。wasmoon 产品 runner 实际报告
  `initialization-failure diagnostic-unavailable: out of memory`。
- S16 为锁定 F1 补齐模块内定义的 f64 全局；语料验证初值的负零位模式及读写一致。
  导入全局仍限 i32/i64。费用模型和诊断 ABI 沿用现有版本。

## 演示结果

| 用例 | Wasmtime 与 wasmoon |
| --- | --- |
| 同为 20 次迭代，Fuel 450 | 短循环返回 190。长循环报 code 1/site 52。 |
| 有限长循环，Fuel 1000 | 返回 2494。 |
| 无限循环，Fuel 15、450、1000 | 每个预算各重复 20 次，均报 code 1/site 20。 |
| 嵌套循环，Fuel 79、80 | 79 在最后一次读取前报 code 1/site 22，已执行的计数为 6。80 返回 6。各重复 20 次。 |
| 深递归，深度上限 33 | 33 活跃帧正常返回 32。进入第 34 帧前报 code 5/site 11。 |
| 两层调用，256 个跨调用存活的 v128 local | 779 栈单位返回 42。778 在原调用报 code 4/site 771。646 在入口报 code 4/site 2。 |
| memory 和 externref table 从 1 增至 2 | 零增长返回旧大小 1；增加 1 恰好达上限。尝试增加 2 或 unsigned 最大值分别报 code 2/site 34、code 3/site 6。 |

## 独立审查

独立子代理以 `/check` 进行只读对抗审查。主代理修复后，子代理重跑原始反例并只读复核。

| 严重程度 | 反例与修复 |
| --- | --- |
| P1 | 定义型 f64 全局以 `-nan:0x1` 初始化时，原审计用浮点相等比较，误拒合法模块。改用浮点位模式比较，并验证 NaN 符号、payload 及负零。复审在两引擎原/插桩模块上读回相同的 `0xfff0000000000001`。 |
| P2 | F2 的 Wasmtime CLI 仅凭 `unreachable` 无法判定诊断。通过独立 core dump 按真实导出索引检查 code 5/site 594，同时断言三入口的实际输出前缀。 |
| P2 | 合成溢出最初只验证独立预言机。增加针对实际生成指令的白盒检查，确认乘法前的无符号阈值、Fuel code 和原 site。 |
| P2 | 嵌套循环最初仅做一次差分。增加原模块、低一单位及恰好预算的 20 次独立实例复验。 |

SIMD 探针进入业务导出前清零，防止只执行 core start 的 SIMD 就通过。复审未发现剩余阻塞项。
