输入。独立验收集包含三个同应用族的新输入和两个微基准。S18 对这五个验收模块

## 独立审查与复验

子代理使用 `/check` 对当前变更做了只读对抗审查，重点覆盖 S18，抽查前置代码。
主代理负责修复。原始计时二进制与补采构建二进制各自保留，构造出的 Wasm 和
sidecar 经报告重放确认逐字节相同。

| 严重程度 | 反例与修复 |
| --- | --- |
| P2 | 缺失体积行或用一条最大档记录冒充完整构建证据。重放对照冻结清单、保留字节、命令、PID、RSS 与阶段日志。 |
| P2 | 有效 Wasm 被删除 start section 或 Fuel-only start 重定向。对最终字节验证 start 存在性，并检查 Fuel-only 原索引。 |
| P2 | wasmoon 将 i64 误当 i32，且负 i32 的位模式比较失败。验证导出签名并正确读取有符号返回结果。正式计时的三份标量产物已独立核对为 `() -> i32`，返回正值。 |
| P2 | 进程中断后可能留下运行中的 worker。中断处理杀死并回收进程组。 |
| P2 | A20 栈审计内部两次 Wasm 校验被合计。现在分别打点，补采全部构建样本。 |
| P2（前置） | CLI 在大小门禁前读完整文件，交付校验也接受同哈希但未知版本或错 profile 的 sidecar。普通输入文件按打开句柄先检查大小再限量读取，verify 核对已知版本和匹配的产物标记。 |
| P3 | 报表输出路径可能覆盖证据。改为独占创建。补采前重新核对历史工件和 worker 身份。 |
