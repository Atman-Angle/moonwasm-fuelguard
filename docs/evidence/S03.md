# S03 证据：调用前栈限制原型

验收日期：2026-11-11。范围见 [S03 任务](../07_任务分片_MoonWasm_Instrument.md#s03-验证调用前栈保护的关键路径)。
探针在 `integration/stack_probe/` 生成最小 WAT 及未加保护的对照，独立汇编、校验和检查编码后的引用映射。

## 复现与引擎配置

使用 [S02](S02.md) 的 Ubuntu 24.04.3 x86_64 WSL2、wasmoon 0.18.0 native release 默认 JIT、
Wasmtime 50.0.0 和 wasm-tools 1.263.0。日志中的三个可执行文件 SHA-256 均与 S02 一致。
Linux 进程栈软限为 8 MiB、硬限无限，wasmoon JIT native fiber 配置 16 MiB。
Wasmtime 显式设置 `max-wasm-stack=524288`，fuel 和 epoch 保持默认关闭。
wasmoon 的 core start 在实例化路径执行，单独记录其引擎栈耗尽。

```bash
mkdir -p _build/s03-stack
set -o pipefail
bash scripts/check-stack-linux.sh 2>&1 | tee _build/s03-stack/run.log
```

驱动退出 0。`run.log` SHA-256 为 `e1fcbd87c42982f82947cd9b0ee886577dffd1163db443b71c1357995ca009c4`。
逐条命令、退出码、工具和产物哈希、原始 stdout/stderr 均位于 `_build/s03-stack/`。
首轮 wasmoon 用空格打印多值、Wasmtime 分行打印。驱动改为比较有序值对，原失败保存在 `run-first.log`。

## A05–A08 可行性验收

| 验收 | 两个引擎的结果 |
| --- | --- |
| A05 栈、深度与失败顺序 | 精确预算通过，栈预算少 1 在进入下一个受管帧前触发 code 4。深度恰好通过，少 1 触发 code 5，同时超限先触发 code 4。256 个 v128 local、32 个活跃 i32 操作数的浅调用也通过了栈预算边界。 |
| A06 入口、引用、递归与返回 | 直接互递归、导出 wrapper、start wrapper、固定表间接 wrapper 均执行。导出、start 和间接 wrapper 分别有进入目标前的失败用例。预算恢复后同一实例再调用，提前 return 的多值和对照一致。 |
| A07 生成路径与诊断 | 计费覆盖存活及即将进入的 wrapper、顺序 reserve/release 和冷路径 reserve→fail→emit。受保护压力用例先写 code 4，发出测试标记后 trap。放宽预算的同形探针达到引擎栈耗尽，且无该标记。 |
| A08 实例生命周期 | 同一实例两次正常调用并累计访问计数，第三次触发 trap。测试宿主门拒绝继续复用，并模拟活跃调用期间的重入请求。访问计数用于证明实例状态延续，生产 Fuel 累计和产品 runner 的弃用、重入策略由后续集成验证。 |

编码后审计确认已有函数索引 1–5 保持原位，新增 wrapper 追加；export、start 和 active element
指向预定 wrapper。表固定为一个 funcref 槽，唯一 import 仍是原对照已声明的 WASI `fd_write`。
探针用这个 import 回显 code 4/5；wasmoon 的受控 trap 退出 1，Wasmtime 退出 134。
引擎栈耗尽可返回相同退出码，驱动同时检查标记与引擎错误文本。start 失败时没有可交给宿主的实例，
回显只是测试观察点。产品宿主必须禁止重入、trap 后弃用实例，并为外层入口及宿主调用保留余量。

## 预算映射与压力余量

只审核本原型的固定模板。每个受管帧按
`C = 128 + 16 × (v128 local 数 + 活跃 i32 操作数数 + 6) + 2 × 128 + 3 × 128` 预留抽象单位。
固定项覆盖基本帧；六个槽覆盖参数、两项结果、两项 scratch local 及表索引。
两个 wrapper 额度覆盖当前仍活跃的 wrapper 和下一次进入 wrapper 的临时开销。
三个 helper 额度覆盖最深的 reserve→fail→emit 链。正常的 release 与该冷路径互斥，复用额度。
最外层另用 512 单位覆盖入口和调度模板，wrapper 首帧在执行检查前已经进入，因此专门测试入口预算少 1 时的冷路径。
辅助帧未引入额外逻辑深度或预算事件。

大帧每帧 5,472 单位。工作深度参数 16，对应 17 个受管递归帧和一个外层入口，预算 93,536 单位。
以同一模板放宽预算，用深度阶梯逐步增加压力。下表适用于直接、固定表间接和 start 三组；直接和间接组从导出路径进入。

| 引擎 | 工作深度 | 最深已测成功 | 首个已测引擎耗尽 | 实测额外递归层数 |
| --- | ---: | ---: | ---: | ---: |
| wasmoon 0.18.0 | 16 | 2,048 | 4,096 | 2,032 |
| Wasmtime 50.0.0 | 16 | 64 | 128 | 48 |

这些数值是同形探针在上述配置下的实测余量。抽象单位不能换算为原生字节，阶梯采样没有测出精确溢出阈值。
跨模板的原生栈上界、生产真实负载和最终 S10–S12 审计仍需独立完成。
