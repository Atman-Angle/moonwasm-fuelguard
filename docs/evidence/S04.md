# S04 证据：fuel-v1 模型与独立预言机

日期：2026-11-11。范围见 [S04](../07_任务分片_MoonWasm_Instrument.md#s04-冻结费用模型与独立计费预言机)。
契约见 [fuel-v1](../implementation/fuel-v1.md)，冻结指纹为
`023d16290ad9842c12d72205609ae7b7c478b11c43c9981363a2b5ee69727ab8`。
MoonBit 模型包含 215 个明确的 opcode 键，覆盖 S01 四个产物 inventory 中并集的 127 个 opcode，
含全部 16 条冻结 SIMD 指令。未知 opcode 返回 None，规则存在与 profile 放行分开。

## A02–A04 的独立期望

| 条目 | 手算依据和验证结果 |
| --- | --- |
| A02 | `direct.wat` 入口常量和调用 5、callee 两次 local.get 加 mul/return 共 5、caller return 1，C=11。预算 10 在 `caller:3` 触发 code 1，11 正常且余额 0，12 正常且余额 1。预算 0、−1 和 i64 最大值加 1 被拒，最大值可用。 |
| A03 | 分臂、br_table、短/长循环、嵌套及长安全前缀使用手写 site 成本。分支与无限循环用例重复 20 次，检查失败 site 和输出前缀。无限循环每次访问支付 loop+br 共 2，预算 9 在 loop site 失败并保留 1。可能 trap 的 load 结束其块，之后的块未预扣。 |
| A04 | 比较长度 0、1、65,536 与 u32 最大值，验证 a 只静态扣一次、动态操作数求值一次、人工乘加超 i64 在同 site 返回 code 1。检查静态 Fuel→资源上限→动态 Fuel→原生操作、直接/间接/外部入口顺序、先栈后深度，以及 grow 失败结果不退款。 |

预言机使用手写路径和 Python 大整数，不导入 MoonBit 规则或块分析器。
MoonBit 白盒测试另行核对 SIMD、拒绝路径、动态系数和边界检查。当前产物交付可核对的规格及预期，
S05–S08 将其用于实际块计划和改写验收。现有粗粒度 FuelPass 仍使用原模型。

## 运行与校准

```bash
python3 -m unittest discover -s integration/fuel_oracle -v
moon check --target wasm --deny-warn
moon test --target wasm
moon info
moon fmt --check
mkdir -p _build/s04-oracle
wasm-tools parse integration/fuel_oracle/direct.wat -o _build/s04-oracle/direct.wasm
wasm-tools validate _build/s04-oracle/direct.wasm
wasmoon run _build/s04-oracle/direct.wasm --invoke run
wasmtime run -W max-wasm-stack=524288 --invoke run _build/s04-oracle/direct.wasm
python3 integration/fuel_oracle/calibrate.py
```

Linux 使用 S02 锁定工具。独立校验退出 0，两引擎执行原始 `direct.wasm` 都返回 42 并退出 0，
产物 SHA-256 为 `c3fc35f5df0113084e58816841bbc47a96d2a8dc45d7dfdd91c0e1572d4a9fdf`。
独立预言机及指纹检查 9/9，MoonBit 71/71。生成接口差异仅增加 fuel-v1 查询和费用类型。

动态长度校准使用每进程 8,192 次 `memory.fill`、一个预热进程和五个采样进程。
wasmoon 的 4 KiB / 1 MiB 中位数为 4.15 / 138.93 ms，Wasmtime 为 7.34 / 149.89 ms。
计时含进程启动，且未插桩。该探针核对按请求字节收费的方向，
不能用来估算单 opcode 的 CPU 时间或引擎性能差异。
