# S13 Linux wasmoon runner 验收

执行日期为 2026-11-16，Git 基线为 `b6a4783`，使用当前工作区。覆盖 docs/07 S13 的 A08、A13 和 A23。

## 构建和使用

`cmd/run` 是独立的 Linux x86_64 native 模块，通过内部 workspace 使用根模块的诊断 ABI。实测锁定 wasmoon 0.18.0 和 wasm_core 0.18.0，嵌入 JIT，优化级别 0，编译进入口和循环检查点。根模块的依赖树只有 Starshine 及其依赖，`cmd/instrument` 仍从根模块单独构建为 Wasm。

```bash
ulimit -s 8192
cd cmd/run
moon run --target native --release . -- ../../_build/hello.fuel.wasm \
  --wasi --allow-import wasi_snapshot_preview1.fd_write --wasi-stdout
```

未指定 `--invoke` 时调用 `_start`。命名导出接受 i32、i64、f32、f64，每个参数使用一次 `--arg`，按原顺序输出标量返回值。WASI Preview 1 需同时启用 `--wasi` 和逐项 `--allow-import`。stdio 继承和 `--wasi-arg` 均显式设置。runner 仅允许 guest 链接 stdio、参数、空环境、时钟、随机和进程退出等接口，外部服务和文件路径能力会被拒绝。

runner 检查进程栈软限至少 8 MiB，显式配置 16 MiB native fiber。它从经验证的 S12 产物全局布局读取预算，接受至多 100,000 抽象栈单位和 128 层逻辑调用。S13 用该配置运行 F0 与 F3、86 层 v128 大帧和 128 层标量递归。已测范围见下表，部署与性能认证仍使用后续门禁。Lisp 的 S12 成功配置为 500,000 单位和 2,048 层，超出此 runner 配置。

## 结果

| 验收 | 实测结果 |
| --- | --- |
| A08 实例生命周期 | 同一 JIT 实例两次调用返回 `1` 和 `2`。Fuel 12 累计耗尽，第三次在 site 2 报 code 1。读取 globals 后关闭 JIT 和 Store，`Store::is_closed()` 为真，第四次调用被拒绝。另一个用例由 guest 实际调用 host 回调，回调尝试进入同一活跃实例时被拒绝。外层调用正常返回 7，随后新调用返回 42。 |
| A13 成功与原生行为 | core start 写入状态，默认 `_start` 读出 42。命名导出返回 `47 -9 1.25 2.5`，NaN 按类别核对。固定表合法槽返回 42，空槽与整数除零报告原生 trap、code 0。原生声明 maximum 导致 `memory.grow` 返回 `-1`，CLI 正常退出 0。F0 与 F3 stdout 匹配锁定样例。WASI `proc_exit(0)` 退出 0，`proc_exit(7)` 退出 1 并保留 guest 状态值。 |
| A13 受控失败 | 真实 S12 插桩产物从宿主读取 code 1–5，配对的 site 分别为 4、3、4、3、3。core start 触发的 Stack trap、实例化数据段越界和 `RLIMIT_AS=1 GiB` 下的实际分配失败都报告 `initialization-failure diagnostic-unavailable` 并退出 1。人为诊断 code 7 或不相容的 code/site 报 `diagnostic-error`，退出 1。 |
| A13 timeout 与 cancel | 20 ms 截止时间分别终止 export 和 core start，报告 `timeout phase=invoke/start`。guest 先写出 `ready`，再发送真实 SIGINT，报告 `cancelled phase=invoke`。两类均退出 1。截止时间与取消在 JIT 检查点生效，阻塞宿主调用不保证立即中断。 |
| A13 栈与其他配置 | 512 个跨递归调用保持存活的 v128 local，函数 C=1,162。86 层正常，压力输入 4,096 先在 site 1546 触发 code 4。标量递归 128 层正常，第 129 层在 site 10 先触发 code 5。栈单位或配置深度超 1、进程栈仅 4 MiB、错误参数、缺失 export、WASI 未启用、未授权或类型不符的 import 均退出 2。 |
| A23 产物契约 | 读取单一精确 profile／模型／ABI 标记和两个诊断 global 的类型、初值与索引。缺失标记、近似标记名、未知 ABI、兼容模式产物、重复标记和截断输入均退出 2。产物标记用于格式兼容检查，发布 manifest 和校验哈希由 S14 验收。 |

## 复现

实测环境为 x86_64 Ubuntu 24.04 WSL2、glibc 2.39、GCC 13.3.0、Linux MoonBit 0.1.20261104（940aa18）、wasm-tools 1.263.0。S12 双引擎回归继续使用 S02 锁定工具。

```bash
set -e
export LC_ALL=C
ulimit -s 8192
mkdir -p _build/s13
(cd cmd/run && moon fmt --check && moon check --target native --deny-warn .) \
  > _build/s13/native-check.log 2>&1
python3 integration/runner/check.py > _build/s13/run.log 2>&1
python3 integration/pipeline/check.py > _build/s13/pipeline-regression.log 2>&1
```

CLI 矩阵共 49 个用例，14 个按预期退出 0、18 个退出 1、17 个退出 2。wasm-tools 独立校验 53 个输入和产物。Linux native 生命周期测试 2/2，S12 双引擎完整管线回归退出 0。

另在 Windows PowerShell 7 使用 MoonBit 0.1.20261016（1af328f）执行根模块的 `moon info`、`moon fmt`、`moon fmt --check`、`moon check --target wasm --deny-warn` 和 `moon test --target wasm`，指定 `--target-dir _build/s13-pwsh`。Wasm 测试 84/84，独立计费预言机 9/9，`git diff --check` 退出 0。
