## 实现和兼容性

使用 `instrument ... --codegen p1` 为 `production-v1` 选择
`p1-helper-v1`。P0 的默认行为、既有 marker 及产物字节保留。P1 marker
追加 codegen 后缀，sidecar 同样写入版本。verify 校验两者匹配，runner
校验并接受已知的两种生产布局。

- [Fuel 模板](../../fuel_pass.mbt) 将相同静态费用和 site 传给一个模块内
  `charge(i64 cost, i32 site) -> ()`。签名和函数追加于原数字索引之后，位于
  Growth helper 与 Stack wrapper 前。无收费站点的模块无需追加 charge。
- [动态费用](../../dynamic_cost.mbt) 仍先验证 unsigned 长度和 i64 数学总成本，再
  传入动态附加值。Growth 的容量失败仍优先于动态附加费用；原生 grow 失败不退费。
- [栈布局](../../stack_layout.mbt) 分析最终 typed frame 和生成调用图。charge
  帧为 13 单位，含 2 个参数、1 个 local、2 个操作数峰值和 8 个固定单位。
  Growth→charge 叠加二者的活跃帧，计费点参数计入调用者操作数峰值，失败路径也参与
  分析。原逻辑调用和 wrapper 使用 layout-independent 的 `stack-v1` 预留。
- [管线审计](../../pipeline_audit.mbt) 检查 helper 定义及原始索引、引用、局部变量
  和 imports。计费模型以及冻结的模型指纹不变。

## 调优集性能对照

同一进程按冻结的随机顺序交错运行原版、P0 与 P1。使用 S18 冻结的调优输入、
生命周期和适用热调用窗口、预算与硬件配置。正式首轮每个引擎、负载、窗口使用
3 个进程，每进程每布局 5 个预热样本和 300 个正式样本。首轮共 59,400 个正式样本，
另有 990 个预热样本及 198 条引擎编译记录。生命周期包含实例化和 core start。
热调用从已初始化实例运行，引擎编译时间单独记录。

首轮 wasmoon 的 F0 两个窗口的 P1 p95 区间跨越 3×，各补采 3 个独立进程，
共 5,400 个正式样本和 90 个预热样本。保留初始和补采的全部观测。
补采后 F0 的生命周期 p95 区间为 2.73–3.61×，热调用 p95 区间为
2.48–3.07×。两项仍未定且按门禁不通过。F0 的中位数区间及四个应用组合窗口的
几何平均区间均已确定超出各自上限，因此 P1 的 A17 结论为 **FAIL**。
独立验收用例留给 S21。
