# S58 · Linux 插桩启动入口与 A20 复测

2026-11-27。按 v4 §4 的构建工程口径，用 Linux 本地安装入口复测 64 KiB、512 KiB 和 4 MiB 三档输入。[v4 规格](../14_FuelGuard生产规格_v4.md) · [S57 基线](S57.md)

Linux 本地安装把 `fuelguard-instrument` 与 `instrument.wasm` 放进同一目录。脚本在启动 `moonrun` 前设置 `MALLOC_ARENA_MAX=1`、`MALLOC_TRIM_THRESHOLD_=16384` 和 `MALLOC_MMAP_THRESHOLD_=16384`，通过 `exec` 传递 CLI 参数和退出码。设置只作用于该次启动的进程及其子进程。发布候选的 Wasm 插桩器 SHA-256 仍为 `7db9137c9838c0c65a574c9fc10aaa44e67154ed9df4545f0c8061239f239d70`。[安装与使用](../implementation/migration-0.2.0.md)

## A20 工程结果 · PASS

环境为 WSL2 `FuelGuard-S26`、Linux x86_64、glibc 2.39 和 MoonBit 1.0 RC。测量进程使用 S57 的 CPU 亲和性。调用者环境未设置这三个分配器变量或 `GLIBC_TUNABLES`。沿用 S57 的冻结输入和完整保护参数，三档各运行三次 Linux launcher。表中两列分别取每档三次观测的最大值。[原始测量命令和退出码](../../_build/s58-release/a20-launcher/commands.jsonl) · [测量汇总](../../_build/s58-release/a20-launcher/summary.json)

最大档达到 10 秒、524,288 KiB 的 A20 工程预算。九次插桩和各自产物的独立 `wasm-tools validate` 均退出 0，产物与对应 S57 基线逐字节一致。S57 另有各档原生构建器的耗时和 RSS。A17 和 A19 的正式证据仍见 S55。[S55 正式独立保留集](S55.md)

在 Linux 上安装入口和 CLI 后，可对 S57 A20 归档解出的某档 `original.wasm` 复现。示例中的 `CPU` 为原始记录中的 `affinity`，输出需使用新路径。正式记录的耗时和 RSS 使用 `bench/run.py` 的 `Run.command` 采集。[S57 A20 归档](../../_build/s57-release/evidence/a20-raw.tar.gz)

```bash
env -u MALLOC_ARENA_MAX -u MALLOC_TRIM_THRESHOLD_ -u MALLOC_MMAP_THRESHOLD_ \
  -u GLIBC_TUNABLES taskset -c "$CPU" /usr/bin/time -v \
  fuelguard-instrument "$INPUT" -o "$OUTPUT" --profile production-v1 \
  --fuel 9223372036854775807 --max-stack-units 100000 --max-call-depth 128 \
  --max-memory-pages 64 --max-table-elements 64
wasm-tools validate "$OUTPUT"
sha256sum "$INPUT" "$OUTPUT"
```
