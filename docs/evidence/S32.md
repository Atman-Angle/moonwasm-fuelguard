旧 F3 的总数包含 488 个内联 guard（12,940 B）和 12 个共享调用站点（182 B）。Fuel v2 的三组 guard 均为内联。F3 guard 数减少 138 个（27.6%），数量及比例均为三组最大。把每个 fuel-v2 span 单独按 19 条重新分块，F1/F2/F3 分别会增加 91/73/123 个 guard。这是保持现行控制流切分时的上限对照。实测最长 span 分别为 123、123、337 条。

内联 guard 冷分支合计从两条旧布局的 11,858 / 9,623 / 7,818 B 降至 5,417 / 4,305 / 2,889 B。这个差额同时反映了站点减少和冷分支缩短。

## 长直线段与接口

`sleb-63`、`sleb-64`、`sleb-8191`、`sleb-8192` 各构造一个 span。实际 `i64.const W` 分别使用 1、2、2、3 个有符号 LEB128 立即数字节。预算恰好为 W 时两引擎正常返回。少 1 时两引擎读到 code 1、site 2。所有 WAST 见证退出 0，无需修复编码器。真实负载的最大 W 分别为 155、155、452，均使用 2 个立即数字节。

Windows PowerShell 7.6.9 / MoonBit `0.1.20261016 (1af328f)` 上 `moon info`、`moon fmt`、`moon check --target wasm --deny-warn`、`moon test --target wasm` 均退出 0。生成接口相较 S31 字节一致，Wasm 109/109，Python 预言机 17/17。S31 双引擎回归也再次通过。[边界表](../implementation/fuel-v2.md) 补齐模板和迁移语义，[指纹](../implementation/fuel-v2.sha256) 按原约定包含文档正文，随文档更新。
