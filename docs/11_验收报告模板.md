## 4. 差异与故障

记录所有差异：case ID、输入哈希、种子、最小样例、预期语义依据、实际现象、分类、修复commit和重跑结果。规范允许差异、环境故障和实现缺陷分开；环境故障未重跑成功不能算通过。未执行/被排除用例的数量与原因必须保留。

单用例机器可读记录至少包含：case_id、gate_id、status、command、exit_code、engine/config、input_hash、output_hash、expected、actual、trap_code、site_id、artifact_paths、seed。不可用诊断使用null加原因，不能用0冒充。

历史 S17 统一入口输出 `fuelguard-acceptance-v1` 格式的 `report.json`。
`status` 是所选分组的结果，`overall` 汇总 A01–A24。`gates` 将门禁 ID
映射到 `checks` 中的实际命令、结果和证据摘要。A14 和 A15 的逐例记录分别位于
`generated/cases.jsonl` 和 `rejected/cases.json`。缩减、重放及目录约定见
[验收入口](../integration/acceptance/README.md)。
